如何在延迟渲染管线中渲染半透明物体

延迟渲染（Deferred Shading）的天性跟半透明是矛盾的——GBuffer 每个像素只存最前面那一个表面的几何/材质，而半透明需要”光线穿透多层”并逐层 α 混合，所以标准延迟管线没法直接吞半透明。工业界的解法本质是绕开或扩充这两点，下面按”为什么难 → 主流怎么做 → 进阶 OIT → 怎么选”讲。

根因：GBuffer 和 α 混合的三重冲突

  1. 单深度：深度测试只留最近片段，半透明要 N 层叠加，单层 GBuffer 存不下
  2. 单材质：位置/法线/反照率每像素一套，多层半透明各有各的 BRDF，混不了
  3. 混合顺序：α 混合要求从后往前（back-to-front），延迟光照是逐像素并行一次性出结果，没有”层”的概念

所以结论先给：标准延迟着色阶段只管不透明，半透明必须另开通道。

方案一（工程主流）：延迟不透明 + 前向半透明

这是 Unity Deferred、UE 的默认路径，也叫 Hybrid / Deferred-Forward。

流程：

  1. Geometry Pass：不透明物体写 GBuffer（含深度）
  2. Lighting Pass：屏幕空间算完所有不透明光照，出一张 opaqueColor
  3. Transparent Pass（切前向）：
    • 复用第 1 步的不透明深度缓冲做深度测试（透明不能穿到不透明后面）
    • 关深度写入，开 GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA
    • CPU 侧对半透明按从后往前粗略排序，逐个物体前向绘制
    • 着色器自己算光照（因为 GBuffer 里没它的数据）

优点：简单、所有引擎都能用、效果可控
代价：

  • 半透明那段要重算光照，光源多就亏（Deferred+ 的做法是把透明那段也改成 Forward+，用 tile/clustered 光列表补）
  • CPU 排序只是近似，物体交错/自遮挡仍有穿帮

💡 UE 里”半透明 = 自动走前向”就是这套；URP 的 Deferred 模式同理，透明物体强制 fallback 到 Forward。

方案二：OIT 系（想要精确、不想排序）

混合管线的”从后往前排序”在物体交错、粒子密集时会崩，于是有了顺序无关透明度（OIT），常见几个变种：

Depth Peeling（剥洋葱）

多次渲染同一场景，每次用上一次的深度做测试，”剥”出第 1 层、第 2 层…第 N 层，最后从里往外混合。

  • 质量好，N 层 = N 个全屏 Pass，开销爆炸，基本只做研究用
  • Dual Depth Peeling 优化到 N/2+1 个 Pass，仍重

Weighted Blended OIT（McGuire & Bavoil 2013）⭐ 实用派

不改硬件、不改排序，改混合算子让它变成顺序无关，近似解。

做法：

  1. 开两个 RT：accum（累颜色）和 reveal（累”可见度”）
  2. 每个透明 fragment 算一个权重 w(a, z)（跟 α 和 view-space 深度有关），accum += Ci * ai * w，reveal += ai * w
  3. 全屏归一化：Cfinal = accum / (reveal + eps)，再跟不透明结果合成
  • ✅ 不用排序、不用存 fragment 链表、移动端/主机都能跑
  • ❌ 是近似，两层靠很近时分不清；权重函数要按项目深度范围调参
  • ❌ 不支持折射（玻璃那种偏 SceneColor 的做不到）
  • 粒子、头发、烟雾首选

PPLL / A-buffer（精确 OIT）

每个像素挂一个链表存所有 fragment，最后逐像素排序混合——精确但内存无上限，要 DX11+ 的 UAV/原子操作，Intel 有 Pixel Sync 方案。CAD、DCC 工具用得多，游戏少见。

方案三：取巧路线

DitherMask（抖动遮罩，UE 常用）

本质还是 Masked/Opaque，用蓝噪抖动做”假半透明”——

  • ✅ 能走完整延迟管线，光照/阴影/Nanite 全吃得到，无排序问题，无 overdraw
  • ❌ 有颗粒感（靠 TAA 抹），做不到真折射

适合：树叶、栏杆、纱网、便宜的”玻璃感”——很多游戏其实大量用这个代替真半透明。

ShaderX7 交错 GBuffer 老法

几何阶段不透明+透明一起写 GBuffer，光照后解交错再混合，省掉前向重算光照但实现重、现在提的人少了。

怎么选

场景 推荐
通用游戏（玻璃、水、角色dissolve） 延迟不透明 + 前向半透明（混合管线）
粒子/烟雾/头发，多层交错 WBOIT 叠加在前向那段上
CAD / 需要像素级精确 Depth Peeling 或 PPLL
植被、栅栏、”假透” DitherMask，当不透明走延迟
大量动态光 + 透明 Deferred+ 不透明 / Forward+ 透明

⚠️ 一个常被忽略的点：半透明+折射是另一个坑。WBOIT / 普通前向都搞不定物理折射（要抓 Screen Color 做偏移），真玻璃一般还是得单独一个折射 Pass 或者靠 GrabPass/SceneColor 采样，这块延迟管线帮不上什么。
