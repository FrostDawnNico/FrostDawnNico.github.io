UE渲染管线

Posted on 2026-07-22

Unreal Engine 渲染管线学习笔记

本文基于当前 Unreal Engine 5.7.4 源码整理，目标是建立对 UE 渲染管线的整体认识，并给出后续源码阅读路径。

核心先记住一句话：

Game Thread 准备视图和场景代理，Render Thread 编排渲染 Pass，RDG 管理资源和依赖，RHI 把命令提交给具体图形 API/GPU。

1. 总体链路

UE 的一帧渲染不是单个函数直接画完，而是跨越多个线程和模块：

  • Game Thread：负责游戏逻辑、世界更新、组件状态、视图构建。
  • Render Thread：负责渲染数据处理、Pass 编排、RDG 构图和执行。
  • RHI Thread：可选线程，用于把 RHI 命令进一步提交给底层图形 API。
  • GPU：执行最终的 draw、dispatch、copy、present 等命令。

3.6 场景数据同步支线（Scene Proxy）

上面讲的是”一帧怎么被画出来”的主线；但 Render Thread 能画的前提，是它手里已经有一份与 Game Thread 解耦的场景数据镜像。渲染线程不能直接依赖 Game Thread 上的 UObject 状态（生命周期不受控、有竞争风险），因此 UE 用 Scene Proxy 模型在两条线程之间同步渲染数据。

三个对象的职责边界（很容易混淆，重点区分）：

对象 线程 职责
UPrimitiveComponent Game Thread 游戏侧组件，持有可见性/材质/变换等业务状态
FPrimitiveSceneProxy Render Thread 组件的渲染代理，渲染线程只读它、不碰组件
FPrimitiveSceneInfo Renderer 内部 场景管理、可见性、绘制命令构建用的数据节点

关键点：

  • 组件的增加、删除、变换更新，都通过 ENQUEUE_RENDER_COMMAND 排队到 Render Thread 执行，保证线程边界清晰。
  • Proxy 在 CreateSceneProxy() 里创建，是”Game Thread 状态”到”Render Thread 数据”的一次性快照 + 后续增量更新。
  • 这条支线是主线的”前置数据准备”：主线里 BeginInitViews 能遍历到的 FPrimitiveSceneInfo，正是这条支线灌进 FScene 的。

4. 延迟渲染主要阶段

FDeferredShadingSceneRenderer::Render() 中的一帧大致可以拆成下面这些阶段。

4.1 帧初始化

主要工作：

  • 初始化 View 和 ViewFamily 的渲染状态。
  • 准备 Ray Tracing 场景。
  • 更新 Virtual Texture。
  • 准备 Lumen、Sky、Reflection 等系统。
  • 初始化 GPU 侧资源状态。

4.2 InitViews

主要工作：

  • 视锥剔除。
  • 遮挡剔除相关准备。
  • 收集动态 Mesh。
  • 为不同 Mesh Pass 准备 draw command。
  • 初始化 View Uniform Buffer。
  • 启动部分阴影相关任务。
