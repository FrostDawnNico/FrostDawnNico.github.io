整理基本知识

类名前的字母

在 UE5 里，类名前的字母是 Epic C++ 编码规范规定的类型前缀，用来在一眼看到类型名时就判断它属于哪一类。虚幻标头工具（UHT）在大多数情况下都要求前缀正确，所以这不是装饰，而是硬性约定。

常见前缀对照

前缀 含义 典型例子
U 继承自 UObject 的类（享受垃圾回收、反射、序列化、蓝图通信等） UActorComponent、UTexture
A 继承自 AActor 的类，可直接 Spawn 到关卡场景中 AActor、ACharacter
F 其他大多数类 / 结构体（普通 C++ 类，不参与 UObject 体系） FVector、FRotator、FString
T 模板类 TArray、TMap、TAttribute
S 继承自 SWidget 的 Slate UI 类 SButton、SCompoundWidget
I 抽象接口类 IAnalyticsProvider
E 枚举 EColorBits
b bool 变量前缀 bPendingDestruction
G 全局对象 GEngine

注：以上规则来自 Epic 官方 C++ 编码规范。

关于 FViewport

FViewport 名字里的 F 是通用前缀——它不属于 UObject 体系，也不是 Actor、不是 Slate 控件、不是模板、不是接口，它就是引擎里的一个普通 C++ 类 / 结构体，所以按规范冠以 F。

💡 顺带一提：F 这个前缀在历史上最早是 Tim Sweeney 写 FVector 那批数学类时取的，源自 Float（浮点），因为当时引擎大量处理浮点运算，F 用来区分浮点版本和其他精度版本的数学结构。后来这个用法扩散到整个引擎的所有”其他类”，最终变成今天的通用前缀——所以它现在并不一定代表 Float，只是沿用下来的”默认前缀”。

记忆要点

  • 看到 U → 有垃圾回收和反射，能挂组件、能进蓝图
  • 看到 A → 能直接丢进场景里的东西
  • 看到 F → 普通 C++ 类型，引擎不替你管生命周期（除非你自己用智能指针）
  • 虚幻标头工具在大部分情况下都需要正确的前缀，因此请务必提供正确的前缀

简单说，前缀是 UE 的”类型标签”，也是 UHT 解析代码、做反射的依据，写自己的类时一定别漏。
