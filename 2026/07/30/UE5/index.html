八条共同经验

SV_Position 反算 UV

全屏 PS 的 VS 只输出 SV_Position, 必须 .xy*TexelSize 反算, 不能声明 TEXCOORD0

临时 RT + 拷贝回写

同纹理采样又写 = 反馈危险; 走临时 RT + AddCopyTexturePass 拷回

Transparent 清除

临时 RT 用 FClearValueBinding::Transparent, 而非 None

不碰 backbuffer

ViewFamilyTexture 即呈现目标, 重定向只会把画面引向屏外

PostConfigInit

插件着色器须在该阶段注册, NewExtension 推迟到 OnPostEngineInit

绝对虚拟路径

着色器 include 用 /Engine/Private/Common.ush, 不依赖相对路径

属性 -> Shader 通路

UPROPERTY 经 Proxy->FLightRenderParameters->FLightShaderParameters->usf 透传

扁平访问 Uniforms

SHADER_PARAMETER_STRUCT_INCLUDE 后在 HLSL 扁平读 DeferredLightUniforms.bXxx

四大思路 · 引擎改造 vs 插件路线

四者关系

▸ DirectionLight = 数据通路地基
▸ · 改引擎, 属性直达像素着色器
▸ SobelEdge = 引擎内后处理样板
▸ OutlinePass = 引擎内网格 Pass 样板
▸ · 借了 Sobel 的屏幕空间思路
▸ Vignette = 不碰引擎的插件实现
▸ 四者共享 RDG 注入范式与坑集

怎么选

▸ 只是后处理效果 -> 优先插件路线 B
▸ 要改网格/材质绑定 -> 引擎级
▸ 想理解引擎数据流 -> 从 DirectionLight
▸ 插件可随工程带走、易维护
▸ 引擎级须重写编译、易随版本冲突
▸ 统一建议: 一致 CVar 命名 + 临时 RT
