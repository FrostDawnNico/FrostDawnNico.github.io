是什么

不是一大堆skeletonmesh

character 不同角色不同效果，但不是每个玩家都有一套自己的skeletonmesh

而是使用组合机制，ABCDE+12345——>A1 A2 …

Spec外观 catalog表 查找 加载资源 外观、组件、动画

解决巨量组合问题，解决多人联机的数据同步问题，解决性能瓶颈

目标：让每个角色外观由“数据配方”驱动，而不是复制一堆网格、材质资产

组合而非复制

外观 = 一组稳定ID的组合

改配色、换部件不新增资产

存档、复制、运营配置都轻量

可存档、可同步

Spec 是纯数据、易序列化

网络只传“小票”，不传资产

核心架构：一条流水线

  1. Spec：菜谱 只存稳定ID：Archetype/Palette/AnimStyle/Voice。可存档可复制。
  2. Catalog：食材柜 ID——>真实资产路径的映射(Archetype网格、调色板颜色)。可运营配置。
  3. Appearance：厨师 解析Spec——>异步加载资产——>应用到角色Mesh/材质（ApplyColors）。
  4. ReplicationComponent：外卖小票 把Spec编码成网络包，服务端权威校验后下发(Encode/Decode)。
  5. Representation/Mass：远桌简餐 近细远粗降级：远处用低价表示，支撑千级角色规模。

UPrimaryDataAsset——UE中的资产类型

UE 里的“资产类型”可以按用途分成几层：渲染/音频/模型这类资源、数据配置类、蓝图/类、世界/关卡，以及 AssetManager 用来做按需加载和打包的“主/次资产”。 UPrimaryDataAsset 属于数据配置里偏“可被集中管理”的那一类。

一、整体分类（常用）

1）基础资源资产（美术/音频/动画）

  • UStaticMesh、USkeletalMesh、UTexture2D、UMaterial/UMaterialInstance
  • USoundWave、USoundCue、UMetaSoundSource
  • UAnimSequence、UAnimMontage、UBlendSpace、UAnimBlueprint
  • UNiagaraSystem、UParticleSystem（旧）
    特点：通常被动硬引用加载，或通过软引用+异步加载；不直接用于“配数值”。

2）数据配置资产

  • UDataAsset（普通数据资产）
  • UPrimaryDataAsset（主数据资产，接 AssetManager）
  • UDataTable（行结构表格）
  • UCurveTable、UCurveFloat、UCurveVector、URichCurve 相关
  • UPrimaryAssetLabel（打包/分块用标签，不是业务数据）
    特点：用来做数据驱动，减少硬编码。

3）蓝图/类资产

  • UBlueprint（含 Actor/Widget/Object 蓝图）
  • UUserDefinedStruct、UUserDefinedEnum
  • UDataAsset 派生蓝图、Primary DataAsset 派生蓝图
    特点：蓝图既是“类”也是资产；Primary 蓝图类还可作为主资产被 AssetManager 按类型发现。

4）世界/关卡/流式

  • UWorld（地图，默认是主资产）
  • ULandscape、UHLODLayer 相关
  • World Partition 下的 UDataLayerAsset / UDataLayerInstance
  • ULevelStreamingDynamic 相关配置
    注意：Data Layer 不是“数值配置”，是 World Partition 里按运行时开关组织 Actor、做流式加载的。

5）配置/元数据类

  • UDataTable、UGameplayTags 设置、Ini 配置、UDeveloperSettings 派生类
  • UPrimaryDataAsset 也可当“全局配置实例”用，但和普通 Ini 配置定位不同。

二、UDataAsset vs UPrimaryDataAsset

UDataAsset（普通）

  • 继承 UDataAsset，在内容浏览器新建“Data Asset”，选你的子类。
  • 就是个带 UPROPERTY 的 UObject 实例，可放数值、软/硬引用、数组、结构体。
  • 加载方式：被别的资产硬引用时跟着加载；或自己用软引用+StreamableManager/AssetManager 手动加载。
  • 没有“全局ID”概念，AssetManager 不会主动按类型扫描它（除非你把它做成 Primary）。
    适合：单个规则配置、项目全局设置、始终随某蓝图加载的小数据。

UPrimaryDataAsset（主数据资产）

  • 继承 UPrimaryDataAsset，重写/利用 GetPrimaryAssetId()，返回 FPrimaryAssetId(Type, Name)。
  • 在 Project Settings → Game → Asset Manager → Primary Asset Types To Scan 注册扫描目录和基类。
  • AssetManager 启动时可发现、建立索引，运行时可按 ID 异步加载/卸载。
  • 支持 Asset Bundle（比如 UI 包只加载图标，Gameplay 包加载网格/音效）、Cook 规则、Chunk 分包。
  • 关卡 UWorld 默认就是主资产，其它普通资产相对它是“次要资产/次级资产”。

简单判断：

  • 永远跟着某角色/某蓝图硬引用加载 → 普通 UDataAsset 够用。
  • 要通过“物品ID/角色ID”动态加载、做背包/商店/英雄池/DLC/分包 → UPrimaryDataAsset。

三、UPrimaryDataAsset 的核心特点

1）唯一标识
FPrimaryAssetId = 资产类型（比如 Weapon）+ 资产名（内容浏览器文件名）。可通过 ID 定位，不依赖硬指针。

2）AssetManager 集中发现
配置扫描目录后，编辑器/打包阶段会索引该类资产；运行时可列出某类型全部ID、按ID加载、按类型批量加载。

3）异步加载与引用管理
C++ 用 UAssetManager::LoadPrimaryAsset / LoadPrimaryAssetsWithType / GetStreamableManager()；蓝图用 Async Load Primary Asset / Load Primary Asset 等节点。避免构造函数硬引用大资产。

4）Asset Bundle 按需加载部分资源
属性上加 meta=(AssetBundles="UI")、"Gameplay" 等，加载资产时可只加载某些 bundle：比如打开商店只加载图标，进战斗再加载网格/特效。

5）Cook / AlwaysCook / Chunk 分包
主资产规则可设 Priority、CookRule、ChunkID。动态ID加载的东西如果不被地图硬引用，可能不会自动打包；用 Primary 规则设 AlwaysCook 或指定 Chunk，做 DLC/补丁/首包瘦身。

6）强类型、可继承、可蓝图化
比 DataTable 更适合“每个对象结构不同/要嵌套/要引用其他主资产/要蓝图子类”的情况。

四、和 DataTable / CurveTable 的取舍

DataTable

  • 行结构继承 FTableRowBase，所有行同构。
  • 适合：武器数值表、道具表、经验表、掉落表、对话表等“很多行同字段”。
  • 支持 CSV/JSON 导入；运行时 FindRow<FRow>(RowName)。
  • 缺点：行结构改了要改结构体并重新导入；不适合每个实例挂大量异质逻辑/多态。

CurveTable / Curve

  • 按行或单曲线存浮点/向量/颜色随变量变化。
  • 适合：伤害衰减、等级缩放、经济曲线、动画权重、成长曲线。

DataAsset / PrimaryDataAsset

  • 单实例对象，字段自由，可放软引用、嵌套结构体、数组、其它主资产ID。
  • 适合：单个武器定义、单个角色定义、技能定义、活动配置、复杂物品（含多网格/多图标/多规则）。
  • 如果还要按ID动态管理 → Primary；如果只是被某蓝图写死引用 → 普通 DataAsset 也行。

经验法则：

  • 同构多行、策划用表格批量改 → DataTable
  • 单对象、字段复杂、要引用资源/要继承 → DataAsset
  • 单对象且要按ID异步、分包、审计、DLC → PrimaryDataAsset

六、常见误区

  • 把 PrimaryDataAsset 当“更高级的DataTable”用：如果只是300行同构数值，DataTable 更省事。
  • Primary 注册了但硬引用到角色蓝图：会失去按需加载意义，重资产要用 TSoftObjectPtr/PrimaryID。
  • 只设了类没设扫描目录：AssetManager 发现不到，按ID加载会找不到。
  • 动态加载的主资产没设 Cook/AlwaysCook：开发模式能跑，打包后可能没 cook 进去。
  • Data Layer 和 DataAsset 名字都带 Data，但完全两件事：前者管关卡Actor流式，后者管业务数据。

实际开发中可以按“物品/角色/技能/任务”分别给一套 PrimaryDataAsset 字段设计和 AssetManager 注册。
