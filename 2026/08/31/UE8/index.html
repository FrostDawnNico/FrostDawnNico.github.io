补充：.Build.cs

在 Unreal Engine（虚幻引擎）中，.Build.cs 文件是 Unreal Build Tool (UBT，虚幻构建工具) 用来编译 C++ 代码的核心配置文件。

为了搞清楚，我们需要从“模块（Module）”这个概念说起。

1. 为什么项目和插件都有 .Build.cs 文件？

在 UE 中，代码不是以“项目”或“插件”为最小单位编译的，而是以“模块（Module）”为最小单位。

  • 项目（Project）：你的游戏项目本身通常至少包含一个模块（比如叫 MyProject），所以项目里会有 Source/MyProject/MyProject.Build.cs。
  • 插件（Plugin）：插件为了给项目提供功能，也必须被编译成模块，所以插件里也会有 Source/MyPlugin/MyPlugin.Build.cs。

简单来说：只要你想让 UBT 编译一段 C++ 代码，你就必须创建一个模块，而每个模块都必须有一个对应的 .Build.cs 文件。 UBT 在编译前会扫描所有的 .Build.cs，读取里面的配置来决定怎么编译这些模块。

2. .Build.cs 文件有什么作用？

.Build.cs 本质上是一个 C# 脚本，它在编译时被执行，返回一个配置对象（ModuleRules），告诉编译器：

  1. 依赖哪些其他模块（最重要）
    • PublicDependencyModuleNames：公开依赖，依赖模块的头文件对你模块的使用者也可见。
    • PrivateDependencyModuleNames：私有依赖，只有你自己能用。
  2. 包含哪些第三方库/头文件路径
    • 比如引入 .lib、.dll 或者自定义 C++ 库。
  3. 定义宏
    • 通过 PublicDefinitions 或 PrivateDefinitions 添加编译宏（比如 MY_MACRO=1）。
  4. 配置编译选项
    • 比如是否开启 RTTI、异常、C++ 标准版本、预编译头的使用方式等。
  5. 区分平台/配置
    • 可以写 if (Target.Platform == UnrealTargetPlatform.Win64) 来针对特定平台做不同配置。

3. 插件和项目中的 .Build.cs 文件一样吗？

语法和基类完全一样，都是继承自 ModuleRules 的 C# 类，但在实际使用中有一些区别：

对比项 项目中的 .Build.cs 插件中的 .Build.cs
本质 配置游戏/项目的模块 配置插件功能的模块
位置 Source/项目名/ 下 Plugins/插件名/Source/模块名/ 下
依赖关系 通常会依赖引擎模块和插件模块 通常只依赖引擎基础模块（如 Core, Engine），尽量保持独立
编译时机 作为主程序的一部分编译 被项目引用时，作为依赖项一起编译
是否有 .Target.cs 有（如 Game.Target.cs） 通常没有（插件不定义独立的编译目标，只是被目标包含）

关键区别总结：

  • 项目的 .Build.cs 是“消费者”，它把需要的插件模块和引擎模块都拉进来。
  • 插件的 .Build.cs 是“提供者”，它应该尽量自给自足，声明自己需要什么，同时避免给项目带来多余的依赖冲突。

4. 一个容易混淆的点：.Build.cs vs .Target.cs

  • .Build.cs：配置单个模块怎么编译（项目和插件都有）。
  • .Target.cs：配置整个编译目标（比如打包成游戏还是编辑器）的全局规则。只有项目会有（如 MyProjectEditor.Target.cs），插件没有，因为插件不能单独生成可执行文件。

总结

  • .Build.cs 是 UE 模块的“编译说明书”。
  • 项目和插件都有它，是因为它们都以模块的形式存在。
  • 写法上完全一样，但在架构上项目模块负责“整合”，插件模块负责“封装”。

如果你正在写插件，记得保持 .Build.cs 里的依赖尽量精简，这样你的插件才能被不同的项目轻松复用！
