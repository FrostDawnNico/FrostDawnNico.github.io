C++基础

内存与数据类型

1️⃣ sizeof和strlen区别：sizeof看的是“占多少内存”，strlen数的是“字符串有几个字符”。

对比项 sizeof strlen
本质 运算符（非函数） 标准库函数
头文件 不需要 <string.h>（C）/ <cstring>（C++）
作用对象 任意类型 / 变量 / 表达式 仅 以\0结尾的字符串
计算内容 所占内存大小（字节） 字符串长度（不含\0）
计算时机 编译期（大多数情况） 运行期
返回值类型 size_t size_t 
int a;
printf("%zu\n", sizeof(a));   // 输出 int 占用的字节数（通常 4）
//编译器在编译阶段就知道类型大小;与数据内容无关
char s[] = "hello";
printf("%zu\n", sizeof(s));   // 6（h e l l o \0）
//包含 '\0'

char s[] = "hello";
printf("%zu\n", strlen(s));  // 5
//从首地址开始;一直数到第一个 '\0';不把 '\0'计入长度

常见易错示例

char *p = "hello";
printf("%zu\n", sizeof(p));   // ❌ 指针大小（4 或 8）
printf("%zu\n", strlen(p));   // ✅ 5

sizeof(p)是指针本身的大小，不是字符串长度

2️⃣ 数组作参数退化为指针

void func(char s[]) {
printf("%zu\n", sizeof(s));  // ❌ 指针大小
}
char s[] = "hello";
printf("sizeof=%zu\n", sizeof(s)); // ✅ 6
printf("strlen=%zu\n", strlen(s)); // ✅ 5

3️⃣ 字节对齐：数据在内存中的起始地址必须是某个值（通常是数据类型大小）的整数倍，以提高 CPU 访问效率。

一次内存读取即可完成（不对齐可能需要多次读取 + 拼接）

📌 空间换时间

对齐规则（重点）
✅ 通用规则（最常见）

基本类型对齐值 = 自身大小

char→ 1 字节
short→ 2 字节
int→ 4 字节
double→ 8 字节

每个成员的对齐值 = 👉 min(自身大小, 编译器默认对齐值)（通常默认 4 或 8（64位常见））

结构体对齐值 = 成员中最大对齐值，结构体总大小必须是其对齐值的整数倍

struct A {
    char c;     // 1 字节
    int i;      // 4 字节
};

偏移量：  0   1   2   3   4   5   6   7
      [c] [pad] [pad] [pad] [i][i][i][i]

sizeof(struct A) == 8 //📌 char后面填充 3 个字节

结构体嵌套的对齐规则：按自身最大成员对齐

struct Inner {
    double d;   // 8
    char c;     // 1
};

struct Outer {
    int i;      // 4
    struct Inner in;
};

Outer对齐值 = max(4(int), 8(struct Inner)) = 8

sizeof(struct Outer) == 24（常见结果）

#pragma pack 的影响

#pragma pack(1)
struct D {
char c;
int i;
};
#pragma pack() // 恢复默认对齐
// #pragma pack(pop)是 弹出之前保存的对齐
sizeof(struct D) == 5

📌 常用于： 网络通信 协议数据 二进制存储

⚠️ 缺点：性能下降、引发平台问题

结构体成员应按“对齐值从大到小”排列，以减少内存补齐，提高内存利用率和访问效率。

struct X {
    char c;
    int i;
    short s;
};
//[c][pad*3][i*4][s*2][pad*2]
//sizeof = 12
struct Y {
    int i;
    short s;
    char c;
};
//[i*4][s*2][c][pad]
//sizeof = 8

结构体内部成员的补齐，是按“自身对齐值”来的，不是统一补齐到结构体中最大的那个类型。

C++11 后的显式对齐

struct alignas(16) S { //显式指定对齐值（只能 ≥ 自然对齐），S的地址是 16 的倍数
    int x;
};
alignof(int);   // 通常 4
特性 #pragma pack alignas
标准属性 编译器指令 C++11 标准
作用方向 降低 / 取消对齐 提高 / 指定对齐
主要目的 节省内存、兼容协议 提升性能、满足硬件要求
影响范围 结构体 / 类整体 类型 / 成员
是否影响 padding ✅ 是 ❌ 不直接
是否影响大小 ✅ 明显 ✅（可能增加）
推荐程度 ⚠️ 慎用 ✅ 推荐
是否安全 ⚠️ 有风险 ✅ 更安全

空类 / 空基类优化（EBO）

struct Empty {};
struct A : Empty {
int x;
};
//sizeof(A)通常为 4（空基类不占空间）

4️⃣ 字节序（Byte Order / Endianness）：大端序和小端序

字节序：多字节数据在内存中的存放顺序。

int x = 0x12345678;//包含 4 个字节。从左到右看：0x12是第1个字节，0x34是第2个字节，0x56是第3个字节，0x78是第4个字节。
类型 含义 内存低地址 → 高地址
大端（Big Endian） 高位在前 12 34 56 78
小端（Little Endian） 低位在前 78 56 34 12

📌 x86 / x64：小端（Little Endian）

int x = 0x12345678;
int c = *(char*)&x ;
std::cout<< c;//输出120

📌 网络协议：大端（Network Byte Order）

判断当前机器字节序

bool isLittleEndian() {
    int x = 1;
    return *(char*)&x == 1; // 返回1为小端序
}

C++ 中的字节序处理函数

网络字节序转换

关键字与修饰符

一句话区分

关键字 核心语义 一句话记忆
const 只读承诺 我不改，你也别想改
static 持久 / 隔离 活得久，或者只在此地活
volatile 易变警告 别瞎优化，随时会变
explicit 禁止隐式 拒绝“悄悄”的类型转换
extern 外部声明 这东西在别处定义了
extern “C” C 风格链接 告诉 C++：按 C 的方式找我
mutable 突破 const 就算是 const，我也得改
1️⃣ constvs volatile

两者都属于类型限定符（CV-Qualifier），但方向相反。

对比 const volatile
含义 不会被程序修改 可能被外部因素修改
优化 允许编译器优化 禁止激进优化
多线程 不保证线程安全 不保证线程安全
典型场景 常量、接口保护 硬件寄存器、信号处理
❌ “volatile可以保证线程安全。”

✅ 纠正：volatile不保证原子性，线程同步请用 mutex或 atomic。

应用场景 作用
局部变量 延长生命周期至程序结束（只初始化一次）
全局变量/函数 限制作用域仅为当前文件（内部链接）
类成员变量 属于类，不属于对象（所有对象共享）
类成员函数 没有 this指针，只能访问 static 成员

3️⃣ externvs extern "C"

这是链接层面的区别。

关键字 层级 作用
extern 变量/函数 声明变量/函数在其他编译单元定义
extern “C” 链接规范 禁用 C++ 的 name mangling（名称修饰） 
// 告诉 C++ 编译器：这个函数是用 C 写的，别改名
#ifdef __cplusplus
extern "C" {
#endif

void c_function();

#ifdef __cplusplus
}
#endif

4️⃣ explicit：单参数构造函数的守护者：防止构造函数进行隐式类型转换。

class A {
public:
    explicit A(int x) {} // 禁止隐式转换
};

A a = 10; // ❌ 编译错误
A b(10);  // ✅ OK

📌 如果不加 explicit，可能会导致意想不到的函数重载匹配。

5️⃣ mutable：打破 const 的特例：允许在 const成员函数中修改成员变量。
📌 使用场景：缓存、日志计数、互斥锁（mutex）等不影响对象逻辑状态的字段。

❓ static constvs #define

特性 static const #define
类型检查 ✅ 有 ❌ 无
作用域 ✅ 有 ❌ 无
调试 ✅ 可见 ❌ 不可见

✅ 结论：C++ 中优先使用 static const或 constexpr。

❓ const static成员变量：类共享，值不变，整型可内初，取址需外定。

当你需要一个属于类且不可变的常量时。替代宏定义，具有类型安全和作用域。

class A {
public:
    static const int x = 5; // 类内初始化
    //因为它们是常量，且属于类，编译器可以在编译期知道它们的值，不需要每个对象都存储一份。
};

非 const static成员：必须在类外定义（分配内存）。

C++11 之前，只有 int、char、bool等整型 const static成员才能在类内初始化。

C++11 起，可以使用 constexpr static来支持非整型：

即使你在类内初始化了 const static成员，如果你需要它的地址（或引用），你仍然需要在类外提供一个定义（不重新初始化）。

❓volatile int* p和 int* volatile p区别？

前者：指向的数据易变。 后者：指针本身易变。

❓static变量线程安全吗？

C++11 起：局部 static 变量初始化是线程安全的。

❓为什么 extern “C”不能重载？

因为 C 语言不支持函数重载，没有 name mangling。

类与结构体

class与struct区别

📌 C++ 中唯一的硬性区别就是默认访问权限。

对比项 class struct
默认访问权限 private public
默认继承方式 private public
设计意图 封装 + 抽象 数据聚合 (POD)
使用场景 业务逻辑、资源管理、复杂对象 数据传输、配置、轻量级结构

📌 若忘记写 public，会导致无法通过基类指针访问派生类。

class Base {
public:
    int x;
};

class Derived : Base {   // ❌ 默认 private 继承
};

Derived d;
d.x = 10;   // ❌ 编译错误：x 不可访问

✅ 正确写法：

class Derived : public Base { };

补充： 访问权限规则

基类成员 public 继承 protected 继承 private 继承
public ✅ public ✅ protected ✅ private
protected ✅ protected ✅ protected ✅ private
private ❌ 不可访问 ❌ 不可访问 ❌ 不可访问

1️⃣ POD（Plain Old Data）

兼容 C ；可安全 memcpy ；无虚函数、无自定义构造

struct更适合做 POD（语义更清晰）

2️⃣ 内存布局完全一致

3️⃣ STL 中凡是只包含数据的辅助结构通常用 struct，而具有强封装和资源管理的用 class。

std::pair、std::tuple→ struct
std::vector、std::string→ class

预处理与宏

关键字 本质 一句话记忆
#define 预处理宏替换 无脑文本替换，不管对错
inline 编译期函数展开建议 想快一点，但不一定真 inline
typedef 类型别名 给类型起个新名字

核心区别

维度 #define inline typedef
处理阶段 预处理 编译期 编译期
类型检查 ❌ 无 ✅ 有 ✅ 有
作用域 ❌ 无 ✅ 有 ✅ 有
调试 ❌ 难 ✅ 可调试 ✅ 可调试
是否安全 ❌ 高风险 ✅ 安全 ✅ 安全
能否递归 ✅ ❌ N/A 
#define SQUARE(x) x * x
int a = SQUARE(1 + 2); // 1 + 2 * 1 + 2 = 5 ❌

#define：没有作用域 ;不能调试 ;容易引发隐藏 Bug

inline int square(int x) {
    return x * x;
}

inline特点： 有类型检查 ;有作用域 ;可调试

❓inline 一定会内联吗？不一定。
只是“建议” ;递归、虚函数、复杂函数通常不会 inline ;现代编译器自动决定是否 inline

inline 常放头文件

typedef int* INTPTR;
INTPTR a, b;  // a 和 b 都是 int*
#define INTPTR int*
INTPTR a, b;  // a 是 int*, b 是 int ❌

C++11 新宠：using

using INT = int;
using Vec = vector<int>;

比 typedef更好：可读性更强；支持模板别名

❓ 用宏写一个 MAX，有什么问题？

#define MAX(a,b) ((a)>(b)?(a):(b))

❌ 问题： 参数可能被求值两次； 有副作用

1️⃣ 自增变量

int a = 1, b = 2;
int m = MAX(a++, b++);

实际执行： a++和 b++各执行一次比较 ；胜出的那个 再执行一次 ++

2️⃣ 函数调用作为参数

int foo() {
printf("foo\n");
return 3;
}

int bar() {
printf("bar\n");
return 2;
}

int m = MAX(foo(), bar());

📌 输出：

foo
bar
foo   ← 可能被调用两次！

📌 结果不可预测，且违反直觉

✅ 正确做法：

  1. 函数模板（推荐）

    template
    inline T max(T a, T b) {
    return a > b ? a : b;
    }

泛型；安全；高性能
2. inline函数（C 风格）

inline int max(int a, int b) {
    return a > b ? a : b;
}

参数只求值一次 ； 有类型检查 ； 可调试

  1. constexpr（C++11+）

    constexpr int max(int a, int b) {
    return a > b ? a : b;
    }

编译期可用

总结：

#define是预处理阶段的纯文本替换，没有类型安全和作用域；

inline是编译期的函数展开建议，保留类型检查和作用域；

typedef用于为类型定义别名，提升代码可读性。

现代 C++ 中，应尽量避免宏，使用 inline和 using。

强制类型转换

能用 C++ 四种 cast，就不要用 C 风格 (Type)value强转。

转换 英文 核心用途 是否安全
static_cast 静态转换 良性转换（数值、父子类） ✅ 相对安全
dynamic_cast 动态转换 多态类型安全检查 ✅ 最安全
const_cast 常量转换 去掉 / 加上 const ⚠️ 高风险
reinterpret_cast 重解释转换 底层比特重解释 ❌ 极危险

1️⃣ static_cast（最常用）

✅ 编译期转换，无运行时开销

double d = 3.14;
int i = static_cast<int>(d);   // ✅3

class Base {};
class Derived : public Base {};

Base* b = new Derived();
Derived* d = static_cast<Derived*>(b); // ✅

int* p = static_cast<int*>(b); // ❌ 无关类型

用于相关类型之间的转换，编译期检查，不能去除 const。

2️⃣ dynamic_cast（多态专用）

✅ 运行时类型检查（RTTI）

class Base {
public:
    virtual ~Base() {} //必须有虚函数✅
};

class Derived : public Base {};

Base* b = new Derived();
Derived* d = dynamic_cast<Derived*>(b);

✅ 成功：返回非空指针

❌ 失败：返回 nullptr（指针）或抛异常（引用）

❌ 没有虚函数 → 编译失败

❓dynamic_cast 为什么要求基类有虚函数？

✅ 因为需要 RTTI（运行时类型信息）

3️⃣ const_cast（最容易被误用）

✅ 唯一能改 const / volatile 的转换

const int x = 10;
int* p = const_cast<int*>(&x); //✅

*p = 20; // ❌ 未定义行为（UB）

const_cast用于移除 const，但修改真正的 const 对象是未定义行为。

int real_value = 10;          // 原始变量不是 const
const int& ref = real_value;  // 只是通过 const 引用“承诺”不改

int* p = const_cast<int*>(&ref);
*p = 20;                     // ✅ 安全，real_value 变为 20

4️⃣ reinterpret_cast（最底层）

✅ 重新解释比特位

int x = 0x12345678;
char* p = reinterpret_cast<char*>(&x);

📌 常用于：网络协议；硬件寄存器；序列化

❓reinterpret_cast是安全的？ ❌它不做任何检查，完全依赖程序员。

与 C 风格强制转换对比

int* p = (int*)&x; // C 风格

❌ 问题：编译器不告诉你做了什么；可能偷偷调用 const_cast+ static_cast

int* p = static_cast<int*>(...); //✅ C++ 推荐写法

总结：
static_cast用于相关类型的静态转换；

dynamic_cast用于多态类型的安全向下转型（需 RTTI）；

const_cast用于移除 const 属性，但修改原 const 对象是未定义行为；

reinterpret_cast用于底层比特重解释，极其危险。

❓ 什么时候必须用 dynamic_cast？

✅ 在多态体系中，不确定实际对象类型时。

❓ static_cast和 dynamic_cast性能差异？

✅ static_cast无运行时开销，dynamic_cast有 RTTI 开销。

❓ reinterpret_cast能转函数指针吗？

✅ 可以，但不可移植，强烈不推荐。
