左值与右值

左值：可寻址、有名字的表达式，如变量。

int a = 10;   // a 左值
string s = "abc"; // s 左值

右值：临时值、无名字、不能取地址、用完即销毁，如函数返回值。

10 + 20;
string("hello"); // 临时对象
func_return_obj(); // 函数返回临时对象

左值引用与右值引用

左值引用 T&：给有名字、持久的变量起别名，不能绑临时值。
右值引用 T&&：给没名字、临时的值起别名，只能绑临时值，实现移动语义，目的：偷资源，不拷贝

左值引用是“借用”不拥有资源，只是给别人的变量起别名。
右值引用是“接管 / 偷”临时对象马上要销毁了，右值引用把它的内存、资源抢过来自己用，不用重新分配，性能极高。

代码示例

int a = 10;        // a 是左值
int& ref = a;      // ✅ 左值引用 绑定 左值

// int& ref = 10;  // ❌ 错误！不能绑定临时值

int&& rref = 10;   // ✅ 右值引用 绑定 临时右值

int a = 20;
// int&& rref = a; // ❌ 错误！不能绑定左值

判断左右值

  1. 高频问题总结

前置自增 ++i：返回左值引用 → 左值
后置自增 i++：返回临时拷贝 → 右值
普通左值引用 T&：只能绑左值
右值引用 T&&：只能绑右值
常量左值引用 const T&：万能引用，左值、右值都能绑

  1. 代码示例

    int a = 1;
    int b = 2;

    a; // 左值（有名字、可取地址）
    a + b; // 右值（临时运算结果）
    100; // 纯右值
    string(“hello”); // 临时对象，右值
    ++a; // 左值（返回自身引用，可连续赋值：++++a）
    a++; // 右值（返回旧值临时副本）

    // A ❌ 报错
    int& r1 = 10;
    // 普通左值引用【不能绑定纯右值】

    // B ✅ 正确
    int&& r2 = 20;
    // 右值引用 专门绑定右值

    // C ✅ 正确
    int x = 5;
    int& r3 = x;
    // 左值引用绑定左值，标准用法

    // D ❌ 报错
    int&& r4 = x;
    // 右值引用【不能绑定普通左值】

右值引用的作用

用于定义移动构造函数、移动赋值运算符

实现移动语义

直接转移堆资源 / 指针所有权，不进行深拷贝

减少内存拷贝与开辟销毁开销，大幅提升性能

对应函数标准签名

// 移动构造
ClassName(ClassName&& other) noexcept;

// 移动赋值
ClassName& operator=(ClassName&& other) noexcept;

❓noexcept关键字作用及优点

移动操作标记为 noexcept，是为了让标准库容器在发生重新分配时能够安全地使用移动语义，从而兼顾异常安全与性能。

一、 noexcept 的作用是什么？

作用：

  • 向编译器和标准库承诺：
    👉 这个函数不会抛出任何异常
  • 如果真的抛出了异常，程序会直接调用 std::terminate

二、 为什么移动构造 / 赋值特别需要 noexcept？

✅ 关键原因：标准库容器的异常安全要求

以 std::vector 为例： 场景：vector 扩容（reallocate）

当容量不足时：

  1. 申请新内存
  2. 把旧元素搬到新内存
  3. 销毁旧元素

❌ 如果移动构造函数没有 noexcept

标准库会这样判断：

“如果这个移动中途抛异常，我已经搬了一半，旧对象还在，还能回滚。”

✅ 安全，但代价大

➡️ 标准库会放弃移动，改用拷贝构造

结果：

  • 性能大幅下降
  • 移动语义形同虚设

✅ 如果移动构造函数有 noexcept

标准库判断：

“这个操作不会抛异常，可以放心移动。”

➡️ 直接使用移动构造

结果：

  • O(n) → O(1)
  • 无额外内存分配
  • 真正的“零开销抽象”

三、noexcept 的核心优点总结

优点 说明
✅ 启用高效移动 vector / map / unordered_map 扩容时使用移动
✅ 异常安全 保证强异常安全（strong exception safety）
✅ 编译器优化 可省略异常处理代码
✅ 符合 STL 设计预期 是“可移动类型”的重要特征
✅ swap / move 算法更安全 std::move_if_noexcept

四、标准库中的典型体现（面试高频）

1️⃣ std::move_if_noexcept

👉 如果移动可能抛异常，就退化为拷贝

2️⃣ std::vector 的行为规则（必背）

条件 vector 扩容行为
移动构造 noexcept ✅ 使用移动
移动构造可能抛异常 ❌ 使用拷贝
不可拷贝 ❌ 编译错误或 terminate

五、什么时候必须写 noexcept？

✅ 强烈建议的场景

  • 移动构造函数
  • 移动赋值运算符
  • 析构函数（C++11 起默认 noexcept）
  • swap 函数

❌ 不建议乱加的场景

  • 可能失败的操作（如内存分配、IO）
  • 调用了可能抛异常的函数

六、标准写法示例

七、面试加分回答

“noexcept 不仅是异常说明，更是接口契约。
对移动构造而言，它是性能开关；
对标准库而言，它是异常安全的前提。”

八、一句话总结

移动构造 / 赋值不加 noexcept，等于白写移动语义。

总结

右值引用结合移动构造、移动赋值，实现移动语义，不再深拷贝数据，而是直接转移资源所有权，减少临时对象开销，大幅提升程序运行性能。

移动语义 Move Semantics

把临时对象的堆资源 / 内存直接转移给新对象，替代昂贵的深拷贝，O (1) 极快。

  1. 移动构造函数

    类名(类名&& 源) noexcept

  2. 移动赋值运算符

    类名& operator=(类名&& 源) noexcept

  3. std::move 强制把左值转为右值，主动触发移动语义。

右值引用&移动语义

强绑定，缺一不可

关系：右值引用是语法基础，移动语义是功能目标。

  • 右值引用是 C++11 新增的类型（T&&），用于识别临时对象；
  • 移动语义是一种优化思想：挪用临时对象资源，而非拷贝；

一句话总结：右值引用是实现移动语义的工具，移动语义是右值引用的核心用途。

完整逻辑链

  1. 编译器遇到临时对象（右值）；
  2. 用右值引用 T&& 精准识别这个临时对象；
  3. 触发移动构造函数 / 移动赋值运算符；
  4. 执行移动语义（偷资源，不拷贝）。

代码示例

#include <cstring>
#include <utility>
class String {
public:
// 普通构造
String(const char* str) {
len = strlen(str);
data = new char[len + 1];
strcpy(data, str);
}

    // 【拷贝构造】：深拷贝（慢）—— 绑定左值
    String(const String& other) {
        len = other.len;
        data = new char[len + 1];
        strcpy(data, other.data); 
    }

    // 【移动构造】：移动语义（快）—— 必须用 右值引用 String&&
    // 如果写好了移动构造函数，编译器会自动选择它
    String(String&& other) noexcept {
        // 直接偷别人的资源，不new内存
        data = other.data;
        len = other.len;

        // 把原临时对象置空，防止它析构时释放资源
        other.data = nullptr;
        other.len = 0;
    }

    ~String() {
        delete[] data;
    }

private:
char* data;
int len;
};

// 返回临时对象（右值）
String createTemp() {
return String("temp");
}

int main() {
// 右边是临时对象 → 被右值引用识别 → 调用移动构造 → 执行移动语义
String s = createTemp();
}

nullptr

C++11引入的nullptr，更安全表示空指针

nullptr类型

nullptr是C++11新引入的类型，用于明确表示空指针，避免了传统NULL的歧义。

与NULL区别

nullptr能区分指针和整数0，避免隐式类型转换错误。而NULL在不同编译环境下可能定义不同。

❓自动类型推导会带来哪些副作用？

  1. 丢失顶层 const / volatile 和引用（auto 的默认行为）

✅ 副作用：

  • 无意中产生拷贝，影响性能
  • 意外允许修改本应只读的变量

📌 面试提示：auto 永远不会保留顶层 const / volatile，除非显式声明。
2. 意外的拷贝与性能问题

✅ 副作用：

  • 对大对象或复杂类型造成性能损耗
  • 修改 x 不影响原容器

✅ 正确做法：

  1. 与初始化列表的奇怪行为

✅ 副作用：

  • 推导结果可能不是你想要的容器或数组
  • 无法进一步推导为 std::vector

📌 C++17 后部分场景有所改进，但仍需警惕。
4. 代码可读性下降（“类型消失”）

✅ 副作用：

  • 读者必须追踪 process 的返回类型
  • 对接口变更不敏感，增加维护成本

📌 建议：局部变量可用 auto，公共 API 返回值慎用

补充回顾：❌ 仅仅返回类型不同的同名函数，在 C++ 中不能构成合法的函数重载
✅ 但在极少数特定情况下（虚函数 + 返回类型协变），它可以成为运行期多态的一部分。

✅ 合法原因：

返回类型是 基类指针 / 引用 → 派生类指针 / 引用

称为 协变返回类型（covariant return type）

仍然属于 运行期多态

📌 注意限制：

仅适用于 指针或引用

仅适用于 虚函数

普通函数仍然不行

  1. decltype 的“引用陷阱”

✅ 副作用：

  • decltype(expr) 若表达式是左值，推导为引用
  • 容易引入悬垂引用

📌 面试高频：decltype ≠ auto
6. 数组退化问题

✅ 副作用：

  • 丢失数组维度信息
  • 影响 sizeof、range-based for 等行为
  1. 与代理对象（Proxy Object）结合时的坑

✅ 副作用：

  • auto 延长临时对象生命周期失败
  • 产生未定义行为或逻辑错误
  1. 影响 API 稳定性

✅ 副作用：

  • 下游代码隐式依赖具体类型
  • 接口微小改动可能引发连锁编译错误

面试总结一句话 ✅

自动类型推导提升了便利性，但可能牺牲精确性、性能和可读性；使用时必须清楚它“不会保留什么”，而不是只看它“推导了什么”。

vector<int> vec = {1,2,3};

重点

忘记 join /detach：线程对象销毁时如果还在运行，程序会直接崩溃。

模板&泛型

C++ 模板（Template） 是泛型编程的核心

作用：类型参数化，编写与类型无关的通用代码，一套代码适配任意类型（int、double、自定义类、容器等）

兼顾复用性、类型安全、编译期效率。

可变参数模板

接收任意个数、任意类型参数，STL tuple、emplace 底层依赖。

template<typename... Args>
void func(Args... args);

// 递归终止
void print() {}

// 可变参数模板
template<typename T, typename... Args>
void print(T first, Args... args)
{
cout << first << " ";
print(args...); // 递归拆解
}

// 调用
print(1, 3.14, "c++", true);

lambda表达式

掌握匿名函数的语法与应用

  1. 基本语法

Lambda表达式定义了一个匿名函数对象，其基本形式为：捕获列表 -> 返回类型 { 函数体 }。

  1. 捕获方式

可以通过值捕获（[x]）、引用捕获（[&x]）或隐式捕获（[=]或[&]）来访问外部变量。

  1. 函数对象

Lambda表达式本质上是一个实现了operator()的类的实例。它可以被赋值给std::function对象，或作为参数传递给STL算法。

  1. 应用场景

Lambda表达式常用于STL算法中作为比较器或操作函数，也广泛应用于异步编程中的回调函数。
