C++ Object-Oriented

Posted on 2026-05-07

面向对象

核心三大特性

特性(英文) 概念
封装(Encapsulation) 将数据和方法包装在一个类中，通过访问控制（public、private、protected）隐藏实现细节，提供清晰的接口，增强代码的安全性和可维护性。
继承(Inheritance) 子类继承父类的属性和方法，可以实现代码复用，并在此基础上进行扩展。通过继承，可以建立类之间的层次关系，体现“is-a”的关系。
多态(Polymorphism) 多态允许通过基类指针或引用调用派生类的虚函数，实现接口的统一和行为的多样性。多态是C++实现运行时多态性的关键机制。

多态实现原理

静态联编与动态联编

静态联编在编译时确定函数调用地址，效率高但不灵活。动态联编在运行时根据对象的实际类型确定函数调用地址，是实现多态的基础。

虚函数表（vtable）与虚指针（vptr）

编译器为每个包含虚函数的类生成一个虚函数表，其中存储了该类所有虚函数的地址。该表在程序启动时创建，并在类的所有对象间共享。

每个包含虚函数的类的实例对象中，都会隐式地包含一个指向其所属类的虚函数表的指针，即vptr。对象通过vptr找到虚函数表，进而调用正确的虚函数。

动态绑定：只有通过基类指针或引用调用虚函数时才会发生动态绑定；直接通过对象调用不会。

虚函数与抽象类

名称 概念
虚函数 在基类中使用virtual关键字声明的函数。派生类可以重写（override）该函数，以提供不同的实现。通过基类指针或引用调用虚函数时，会根据对象的实际类型调用相应的函数实现。
纯虚函数 在基类中声明但不提供实现的虚函数，其语法为virtual 返回类型 函数名() = 0;。包含纯虚函数的类称为抽象类，不能实例化，常用于定义接口（interface）。
抽象类 抽象类不能被实例化，只能作为基类被继承。派生类必须重写基类中的所有纯虚函数，否则该派生类也是抽象类。抽象类提供了一种定义接口的机制，强制要求子类遵循统一的规范。

关键关键字

关键字 概念
override 显式告诉编译器重写基类虚函数，如果签名不匹配会报错，防止手写错误。
final 禁止类被继承或虚函数被重写。
virtual 析构函数 基类析构函数必须声明为 virtual，否则通过基类指针删除派生类对象时，会导致派生类资源泄漏（只调用了基类析构）。

虚函数表深度剖析

多重继承与vptr

在多重继承中，对象可能包含多个vptr，分别指向不同基类的虚函数表。这使得通过不同基类指针调用虚函数时，能正确找到目标函数。

性能开销

虚函数调用需要通过vptr和虚函数表进行一次间接寻址，相比普通函数调用有轻微的性能开销。但现代CPU的分支预测能很好地优化这种开销。

vtable布局

虚函数表是一个函数指针数组，按虚函数在类中声明的顺序存放。如果类有多个基类，可能会有多个虚函数表。

vptr初始化

对象在构造时，其vptr会被初始化为指向其最终派生类的虚函数表。在构造函数执行期间，vptr会指向当前正在构造的类的虚函数表。

❓重载、重写、隐藏的区别

重载发生在同一作用域内且函数名相同但参数不同；重写发生在父子类之间且用于实现运行时多态；隐藏是由于作用域遮蔽导致基类函数在派生类中不可见。

特性 重载 (Overload) 重写 (Override) 隐藏 (Hide)
作用域​ 同一作用域（如同一个类内） 父子类作用域​ 父子类作用域​
函数签名​ 必须不同（参数类型、个数、顺序不同） 必须完全相同（C++11后支持协变返回类型） 可以相同，也可以不同​
Virtual关键字​ 无关（有无virtual均可） 基类必须有 virtual​ 无关（有无virtual均可）
绑定时机​ 编译期（早绑定） 运行期（晚绑定，通过vtable） 编译期（静态绑定）
目的​ 提供同名函数的不同版本 实现多态，改变基类行为 派生类函数屏蔽基类同名函数

  1. 重载 (Overload)：编译期的静态多态

重载关注的是参数的多样性。只要参数列表不同，即使返回值不同，也算重载（但仅返回值不同不算重载）。

class Printer {
public:
    void print(int i) { cout << "Int: " << i << endl; }
    void print(double d) { cout << "Double: " << d << endl; } // 重载
    void print(string s) { cout << "String: " << s << endl; } // 重载
};

为什么返回值不能作为重载依据？因为函数调用时可以不接收返回值，编译器无法仅凭返回值判断调用哪个函数。

  1. 重写 (Override)：运行期的动态多态

重写是实现运行时多态的关键。它要求基类函数是虚函数，且派生类重新定义了该函数。

class Base {
public:
    virtual void func() { cout << "Base" << endl; } // 虚函数
};

class Derived : public Base {
public:
    void func() override { cout << "Derived" << endl; } // 重写
};

关键约束：

函数签名完全一致（C++11允许返回类型是基类返回类型的派生类，称为协变返回类型 Covariant Return Types）。

访问权限可以改变（如基类是 private virtual，派生类可以是 public override）。

override关键字：强烈建议使用，能让编译器帮你检查是否真的重写了基类函数，防止因拼写错误或签名不匹配导致的“假重写”。

  1. 隐藏 (Hide)：作用域的遮蔽

隐藏是一个容易踩坑的机制。只要派生类定义了与基类同名的函数（无论参数是否相同），基类的同名函数在派生类作用域中就会被隐藏。

class Base {
public:
    void foo() { cout << "Base foo" << endl; }
    virtual void bar(int x) { cout << "Base bar int" << endl; }
};

class Derived : public Base {
public:
    void foo() { cout << "Derived foo" << endl; }        // 隐藏 Base::foo()
    void bar(double x) { cout << "Derived bar double" << endl; } // 隐藏 Base::bar(int)
};

// 使用示例
Derived d;
d.foo();      // 调用 Derived::foo()
d.bar(10);    // 调用 Derived::bar(double)，int 被隐式转换为 double
// d.Base::foo(); // 必须通过作用域运算符显式调用

陷阱：如果派生类写了一个参数不同的函数，误以为是重载，实际上是隐藏了基类的函数，导致无法通过派生类对象直接调用基类版本。

❓Q：基类的构造函数能否被重写？

A：不能。构造函数和析构函数都不能被重写。虽然派生类可以定义同名构造函数，但这属于重载或独立定义，不属于多态。析构函数必须是虚函数（virtual）才能被正确调用（属于重写的一种特殊形式）。

❓Q：如何在派生类中保留被隐藏的基类函数？

A：使用 using声明。在派生类中使用 using Base::funcName;，可以将基类的同名函数引入派生类作用域，从而实现真正的重载，而不是隐藏。

❓Q：virtual关键字在派生类重写时可以省略吗？

A：语法上可以（一旦基类声明为 virtual，派生类无论是否加 virtual 都是虚函数），但工程规范上建议加上或配合 override使用，以提高代码可读性。

补充：进阶与设计思想

  1. RAII（Resource Acquisition Is Initialization）

将资源（内存、文件句柄、锁）的生命周期绑定到对象上。面试高频术语。它是 C++ 区别于 Java/C# 的重要特征。

应用：智能指针（std::unique_ptr, std::shared_ptr）是 RAII 的最佳实践。

  1. 接口隔离与依赖倒置

面向接口编程，而非面向实现编程。利用抽象类（接口）降低模块间的耦合度。

  1. 多态的替代方案（现代 C++ 视角）

CRTP（奇异递归模板模式）：用模板实现静态多态，避免虚函数带来的运行时开销。

std::variant+ std::visit：在某些场景下替代继承和虚函数，提供更安全的类型处理。
