C++ Object-Oriented

Posted on 2026-05-07 Edited on 2026-05-16

深入剖析C++面向对象的核心机制，包括多态的实现原理、虚函数表以及抽象类的设计。

面向对象

核心三大特性

特性(英文) 概念
封装(Encapsulation) 将数据和方法包装在一个类中，通过访问控制（public、private、protected）隐藏实现细节，提供清晰的接口，增强代码的安全性和可维护性。
继承(Inheritance) 子类继承父类的属性和方法，可以实现代码复用，并在此基础上进行扩展。通过继承，可以建立类之间的层次关系，体现“is-a”的关系。
多态(Polymorphism) 多态允许通过基类指针或引用调用派生类的虚函数，实现接口的统一和行为的多样性。多态是C++实现运行时多态性的关键机制。

多态实现原理

静态联编与动态联编

静态联编在编译时确定函数调用地址，效率高但不灵活。动态联编在运行时根据对象的实际类型确定函数调用地址，是实现多态的基础。

虚函数与抽象类

名称 概念
虚函数 在基类中使用virtual关键字声明的函数。派生类可以重写（override）该函数，以提供不同的实现。通过基类指针或引用调用虚函数时，会根据对象的实际类型调用相应的函数实现。
纯虚函数 在基类中声明但不提供实现的虚函数，其语法为virtual 返回类型 函数名() = 0;。包含纯虚函数的类称为抽象类，不能实例化，常用于定义接口（interface）。
抽象类 抽象类不能被实例化，只能作为基类被继承。派生类必须重写基类中的所有纯虚函数，否则该派生类也是抽象类。抽象类提供了一种定义接口的机制，强制要求子类遵循统一的规范。

虚函数：

虚函数（Virtual Function）的核心作用是实现“运行期多态”（Runtime Polymorphism）。它允许你通过基类的指针或引用调用派生类的方法，从而在不知道对象具体类型的情况下，执行正确的业务逻辑。

核心机制：动态绑定（Dynamic Binding）：虚函数通过 虚函数表（vtable）和 虚指针（vptr）实现：对象内部有一个指针指向类的虚函数表，运行时通过这个表找到实际的函数地址。

关键作用：

场景 作用描述 示例
统一接口 定义一个通用接口（基类），具体实现由不同派生类完成。 Shape基类定义 draw()，派生类 Circle、Square各自实现绘制逻辑。
框架设计 编写通用的算法或框架，允许用户通过继承插入自定义逻辑。 Qt 的事件处理函数 eventFilter()，游戏引擎的 Update()循环。
资源安全管理 基类析构函数必须是虚函数，确保删除基类指针时，派生类的析构函数能被正确调用，防止内存泄漏。 Base* p = new Derived(); delete p;（若 ~Base()非 virtual，则 Derived的资源不会被释放）。

编译器为每个包含虚函数的类生成一个虚函数表，其中存储了该类所有虚函数的地址。该表在程序启动时创建，并在类的所有对象间共享。

每个包含虚函数的类的实例对象中，都会隐式地包含一个指向其所属类的虚函数表的指针，即vptr。对象通过vptr找到虚函数表，进而调用正确的虚函数。

动态绑定：只有通过基类指针或引用调用虚函数时才会发生动态绑定；直接通过对象调用不会。

class Animal {
public:
    virtual void speak() { // 虚函数
        cout << "Animal speaks" << endl;
    }
    virtual ~Animal() {} // 虚析构函数（极其重要）
};

class Dog : public Animal {
public:
    void speak() override { // 重写
        cout << "Dog barks" << endl;
    }
};

void letItSpeak(Animal* animal) {
    animal->speak(); // 运行时决定调用谁
}

int main() {
    Dog dog;
    letItSpeak(&dog); // 输出 "Dog barks"
}

❓虚函数有什么缺点

性能开销：调用时需要查表（vtable），比普通函数稍慢（通常可忽略，但在高频循环中需注意）。

内存开销：每个包含虚函数的类对象都会多存储一个 vptr（通常是 8 字节）。

无法内联：虚函数通常不能被内联优化（inline）。

补充：现代 C++ 的替代方案：

CRTP（奇异递归模板模式）：使用模板在编译期实现多态，消除运行时开销。

std::variant+ std::visit：用于替代继承体系，实现类型安全的“访问者模式”。

final关键字：如果某个派生类不需要再被继承，使用 final修饰虚函数可以帮助编译器优化。

关键关键字

关键字 概念
override 显式告诉编译器重写基类虚函数，如果签名不匹配会报错，防止手写错误。
final 禁止类被继承或虚函数被重写。
virtual 析构函数 基类析构函数必须声明为 virtual，否则通过基类指针删除派生类对象时，会导致派生类资源泄漏（只调用了基类析构）。

虚函数表深度剖析

多重继承与vptr

在多重继承中，对象可能包含多个vptr，分别指向不同基类的虚函数表。这使得通过不同基类指针调用虚函数时，能正确找到目标函数。

性能开销

虚函数调用需要通过vptr和虚函数表进行一次间接寻址，相比普通函数调用有轻微的性能开销。但现代CPU的分支预测能很好地优化这种开销。

vtable布局

虚函数表是一个函数指针数组，按虚函数在类中声明的顺序存放。如果类有多个基类，可能会有多个虚函数表。

vptr初始化

对象在构造时，其vptr会被初始化为指向其最终派生类的虚函数表。在构造函数执行期间，vptr会指向当前正在构造的类的虚函数表。

常见考题

重载、重写、隐藏的区别

重载发生在同一作用域内且函数名相同但参数不同；重写发生在父子类之间且用于实现运行时多态；隐藏是由于作用域遮蔽导致基类函数在派生类中不可见。

特性 重载 (Overload) 重写 (Override) 隐藏 (Hide)
作用域 同一作用域（如同一个类内） 父子类作用域 父子类作用域
函数签名 必须不同（参数类型、个数、顺序不同） 必须完全相同（C++11后支持协变返回类型） 可以相同，也可以不同
Virtual关键字 无关（有无virtual均可） 基类必须有 virtual 无关（有无virtual均可）
绑定时机 编译期（早绑定） 运行期（晚绑定，通过vtable） 编译期（静态绑定）
目的 提供同名函数的不同版本 实现多态，改变基类行为 派生类函数屏蔽基类同名函数
  1. 重载 (Overload)：编译期的静态多态

重载关注的是参数的多样性。只要参数列表不同，就算重载。

class Printer {
public:
    void print(int i) { cout << "Int: " << i << endl; }
    void print(double d) { cout << "Double: " << d << endl; } // 重载
    void print(string s) { cout << "String: " << s << endl; } // 重载
};
  1. 重写 (Override)：运行期的动态多态

重写是实现运行时多态的关键。它要求基类函数是虚函数，且派生类重新定义了该函数。

class Base {
public:
    virtual void func() { cout << "Base" << endl; } // 虚函数
};

class Derived : public Base {
public:
    void func() override { cout << "Derived" << endl; } // 重写
};

关键约束：

基类函数必须声明为 virtual。

函数签名完全一致（函数名、参数列表、const属性相同）

返回类型必须兼容（通常是相同类型，C++11允许返回类型是基类返回类型的派生类，称为协变返回类型 Covariant Return Types）。

访问权限可以改变（如基类是 private virtual，派生类可以是 public override）。

override关键字：强烈建议使用，能让编译器帮你检查是否真的重写了基类函数，防止因拼写错误或签名不匹配导致的“假重写”。

  1. 隐藏 (Hide)：作用域的遮蔽

隐藏是一个容易踩坑的机制。只要派生类定义了与基类同名的函数（无论参数是否相同），基类的同名函数在派生类作用域中就会被隐藏。

class Base {
public:
    void foo() { cout << "Base foo" << endl; }
    virtual void bar(int x) { cout << "Base bar int" << endl; }
};

class Derived : public Base {
public:
    void foo() { cout << "Derived foo" << endl; }        // 隐藏 Base::foo()
    void bar(double x) { cout << "Derived bar double" << endl; } // 隐藏 Base::bar(int)
};

// 使用示例
Derived d;
d.foo();      // 调用 Derived::foo()
d.bar(10);    // 调用 Derived::bar(double)，int 被隐式转换为 double
// d.Base::foo(); // 必须通过作用域运算符显式调用

陷阱：如果派生类写了一个参数不同的函数，误以为是重载，实际上是隐藏了基类的函数，导致无法通过派生类对象直接调用基类版本。

❓Q：基类的构造函数能否被重写？

A：不能。构造函数和析构函数都不能被重写。虽然派生类可以定义同名构造函数，但这属于重载或独立定义，不属于多态。析构函数必须是虚函数（virtual）才能被正确调用（属于重写的一种特殊形式）。

❓Q：如何在派生类中保留被隐藏的基类函数？

A：使用 using声明。在派生类中使用 using Base::funcName;，可以将基类的同名函数引入派生类作用域，从而实现真正的重载，而不是隐藏。

❓Q：virtual关键字在派生类重写时可以省略吗？

A：语法上可以（一旦基类声明为 virtual，派生类无论是否加 virtual 都是虚函数），但工程规范上建议加上或配合 override使用，以提高代码可读性。

现代 C++ 最佳实践：override用于显式声明重写，final用于禁止后续派生类重写该函数，这能有效防止因签名不匹配导致的隐藏错误。

C++类对象的初始化和析构顺序

类对象的初始化遵循“由内而外”（先父类后子类），析构遵循“由外而内”（先子类后父类）。此外，成员变量严格按照在类中声明的顺序进行初始化，而非构造函数初始化列表中的顺序

初始化（Construction）：分配内存-成员初始化（成员变量在类中声明的顺序）-构造函数体执行

析构（Destruction）：析构函数体执行-成员销毁（声明的逆序）-释放内存

静态对象与局部对象的生命周期

对象类型 初始化时机 析构时机 特点
局部对象 执行到定义语句时 离开作用域时 栈上对象，遵循 RAII。
静态局部对象 首次执行到定义语句时 main 函数结束后 C++11 起线程安全。
全局/静态对象 main 函数执行之前 main 函数结束后 初始化顺序在不同编译单元间是未定义的（经典坑点）。

重点

  1. 初始化列表顺序：始终让初始化列表的顺序与类内声明顺序一致，否则是未定义行为。

  2. 虚析构函数的必要性:

    Base* p = new Derived(); delete p;

如果 Base的析构函数不是 virtual，只会调用 Base::~Base()，导致 Derived部分的资源泄漏。

  1. 委托构造函数：如果一个构造函数调用另一个构造函数（C++11），被调用的构造函数先执行完毕，再执行本体的函数体。

析构函数可以抛出异常吗？

析构函数语法上允许抛出异常，但在工程实践和面试回答中，结论必须是：绝对不应该抛出，且应标记为 noexcept。

如果析构函数在栈展开（Stack Unwinding）过程中抛出异常，会导致程序立即终止（std::terminate）。因此，所有资源释放逻辑必须吞掉异常或在内部处理。

核心原因：双重异常的致命性

当程序因异常退出作用域时，会启动栈展开机制，依次调用局部对象的析构函数来清理资源。

假设第一个异常已经抛出，程序正在执行栈展开。此时，某个对象的析构函数又抛出了第二个异常。C++ 标准规定，同时存在两个活跃异常时，必须调用 std::terminate()终止程序。这意味着资源泄露和调试困难。

针对析构函数中可能发生的错误，有三种处理方式，其中“吞掉异常”是最常用的保底手段。

策略 做法 适用场景 评价
吞掉异常 (Swallow) 在析构函数内部使用 try-catch捕获所有异常，不向外传播。 析构函数必须完成的操作（如关闭文件、释放内存）。 最安全。牺牲错误报告，保全程序不崩溃。
终止程序 (Abort) 捕获异常后记录日志，然后调用 std::abort()。 发生不可恢复的逻辑错误（如数据严重损坏）。 比 terminate稍好，能留下日志，但程序依然挂掉。
提供普通接口 (Best Practice) 提供一个 close()或 release()方法让用户显式处理异常。 数据库连接、网络套接字等资源。 最佳设计。将错误处理的责任交给调用者，析构函数只做保底清理。 
class BadExample {
public:
    ~BadExample() {
        // 危险！如果 close() 抛异常，且此时正在栈展开，程序直接 terminate
        close_resource();
    }
}; //❌

class GoodExample {
public:
    // C++11 起，析构函数默认是 noexcept(true)
    // 显式声明是最佳实践
    ~GoodExample() noexcept {
        try {
            // 尝试释放资源
        release_resource();
        } catch (...) {
            // 1. 记录日志
            // 2. 吞掉异常，绝不让它逃出析构函数
            // log("Release resource failed.");
        }
    }

    // 提供显式接口供用户处理异常
    void close() { 
        release_resource(); // 这里抛异常由调用者处理
    }
};

现代 C++ 标准与 noexcept

自 C++11 起，析构函数默认是 noexcept的。这意味着即使你没有写 throw()，编译器也会阻止异常传出。

❓析构函数可以声明为 noexcept(false)吗？技术上可以，但这会破坏容器（如 std::vector）在重新分配内存时的异常安全性保证，极度不推荐。

总结： 在栈展开期间抛异常会导致 std::terminate，应通过显式接口处理错误，析构函数内部使用 try-catch吞掉异常并标记为 noexcept

深拷贝和浅拷贝

核心区别在于是否独立复制指针所指向的动态资源。如果类中含有指针成员，默认的拷贝构造函数执行的是浅拷贝，这会导致多个对象共享同一块内存，极易引发重复释放（Double Free）或内存泄漏。

维度 浅拷贝 (Shallow Copy) 深拷贝 (Deep Copy)
资源占用 源对象与目标对象共享同一份堆内存地址。 源对象与目标对象拥有各自独立的堆内存副本。
默认行为 C++ 编译器默认生成的拷贝构造函数/赋值运算符。 必须由开发者手动实现。
风险 极易导致 Double Free（同一内存被释放两次）或悬空指针。 实现复杂，若处理不当可能导致内存泄漏或自赋值错误。
适用场景 不含指针成员的类，或明确需要共享资源的场景（如 shared_ptr）。 Rule of Three/Five：只要类管理堆内存，就必须实现深拷贝。 
// 浅拷贝风险
class Shallow {
public:
    int* data;
    Shallow(int d) { data = new int(d); }
    // 编译器生成默认拷贝构造函数：data = other.data (仅复制地址)
    ~Shallow() { delete data; } // 隐患在此
};

Shallow s1(10);
Shallow s2 = s1; // 浅拷贝发生
// s1.data 和 s2.data 指向同一块内存
// 析构时：s2 先 delete -> s1 再 delete -> 程序崩溃 (Double Free)

//深拷贝实现
class Deep {
public:
    int* data;
    Deep(int d) { data = new int(d); }

    // 自定义拷贝构造函数（深拷贝）
    Deep(const Deep& other) {
        data = new int(*other.data); // 关键：开辟新内存并复制值
    }
    
    // 拷贝赋值运算符（需处理自赋值和旧资源）
    Deep& operator=(const Deep& other) {
        if (this == &other) return *this; // 1. 防自赋值
        delete data;                      // 2. 释放旧资源
        data = new int(*other.data);      // 3. 分配新资源
        return *this;
    }
    
    ~Deep() { delete data; }
};

重点

  1. Rule of Three：如果一个类需要自定义析构函数、拷贝构造函数或拷贝赋值运算符中的任何一个，那么它几乎肯定需要全部三个。

原因：你需要析构函数来释放资源，就需要拷贝构造和赋值运算符来管理资源的复制，防止浅拷贝带来的冲突。

  1. 现代 C++ 的解法（Rule of Zero） ：最好的深拷贝管理方式是不直接管理裸指针。

使用 std::string、std::vector或 std::unique_ptr。这些标准库容器已经实现了深拷贝语义，你的类只需组合它们，编译器生成的默认拷贝就是安全的（深拷贝）。

补充：写时拷贝 (COW)：拷贝时暂时共享内存，直到其中一个对象试图修改数据时，才进行深拷贝。历史上（如早期的 std::string），为了优化性能，曾使用“写时拷贝”技术。
现代 C++ 标准（C++11 及以后）为了保证线程安全，基本已废弃 COW 机制，现在的 std::string通常是强制深拷贝的。

多态的实现方式

运行时多态（动态多态）和编译时多态（静态多态）。

运行时多态（Run-time Polymorphism）

是传统面向对象编程的核心，依赖于继承 + 虚函数。

  1. 核心机制：虚函数表（vtable）与虚指针（vptr）

底层原理：

vtable：当一个类包含虚函数时，编译器会为该类生成一个虚函数表（本质上是函数指针数组），存储该类所有虚函数的地址。

vptr：该类的每个对象在内存中都会隐含一个 vptr（虚指针），指向所属类的 vtable。

调用过程：当通过基类指针/引用调用虚函数时，程序会通过 vptr 找到 vtable，再根据索引找到实际的函数地址并执行（动态绑定）。
2. 实现条件

公有继承（Public Inheritance）：通常遵循 is-a 关系。

基类声明 virtual：成员函数必须声明为虚函数。

指针或引用调用：必须通过基类的指针或引用来操作派生类对象。

编译时多态（Compile-time Polymorphism）

在编译阶段就确定了调用关系，无运行时开销。

函数重载 (Overloading):在同一作用域内，函数名相同但参数列表不同，编译器根据参数匹配函数。

模板 (Templates):泛型编程，编译器根据具体类型实例化具体的函数或类。

运算符重载:重新定义运算符的行为（如 operator+）。

现代 C++ 中的高级实现

为了避免虚函数的性能损耗，考虑以下替代方案：

  1. CRTP（奇异递归模板模式）

原理：让派生类继承自一个以自身为模板参数的基类 template class Base。

优势：将虚函数调用转化为静态调用，既保留了多态的接口形式，又消除了运行时开销。

template <typename Derived>
class Base {
public:
    void interface() {
        static_cast<Derived*>(this)->implementation(); // 静态多态
    }
};
  1. std::variant+ std::visit

原理：不使用继承，而是将不同类型的对象放入 variant，通过 visit访问者模式分发调用。

优势：类型安全，避免了虚函数表的管理，适合封闭类型的多态场景。

  1. std::function+ lambda

通过回调函数实现行为多态，常用于策略模式的实现。

重点与陷阱

构造函数/析构函数中的虚函数：在这两个函数中调用虚函数，不会发生多态。因为在构造/析构期间，对象的动态类型是当前正在构造/析构的类型，而不是派生类。

切片问题（Slicing）：如果通过值传递（而非指针/引用）将派生类对象赋给基类对象，派生类特有的部分会被“切掉”，多态失效。

总结： 设计选择上，优先使用静态多态（模板）以获得性能，必要时使用动态多态以实现运行时灵活性。使用 override和 final 提高代码的健壮性。

this指针

定义：this是 指向调用该成员函数的当前对象的指针。

本质：在物理实现上，this是成员函数的隐式第一个参数。编译器在编译时会将 obj.func()转化为 Class::func(&obj)。

存储位置：this指针通常存储在栈帧中（作为函数的形参），而不是对象内部。因此，sizeof(Object)不包含 this指针的大小。

关键应用场景

  1. const修饰符作用于 this指针。

非 const 成员函数：this的类型是 Class* const this（指针不可改，指向内容可改）。

const 成员函数：this的类型是 const Class* const this（指针和指向内容都不可改）。

例外 mutable：即使在 const 成员函数中，mutable修饰的成员变量仍然可以被修改（常用于缓存、计数器）。

  1. 区分成员变量与同名参数

当形参名与成员变量名相同时，必须使用 this->来指明成员变量。

class Person {
    int age;
public:
    Person(int age) {
        this->age = age; // 区分成员变量和参数
    }
};
  1. 自赋值检查（Rule of Three）

在重载赋值运算符（operator=）时，必须使用 this来检查是否为自赋值，防止资源释放错误。

MyString& operator=(const MyString& rhs) {
    if (this == &rhs) // 关键检查：防止 obj = obj;
        return *this;
    // ... 正常拷贝逻辑
}
  1. 实现链式调用（Fluent Interface）

通过返回 *this的引用，可以实现连续调用。

class Counter {
    int count;
public:
    Counter& add(int x) { count += x; return *this; }
    Counter& sub(int x) { count -= x; return *this; }
};
// 使用：counter.add(5).sub(3);

重点

❓this指针可以为空吗？

可以（在特定条件下）。如果在调用成员函数前，对象指针已经是 nullptr，且没有访问任何成员变量（不解引用 this），程序可能不会立刻崩溃。

但这属于未定义行为（UB），因为成员函数需要通过 this指针访问对象数据，当 this为空时，任何对成员变量的访问都会导致非法内存访问。

通常会使用 assert(this != nullptr)或智能指针来规避空指针调用。

❓静态成员函数有 this吗？

没有。静态成员函数属于类本身，不依赖于特定对象实例，因此没有 this指针。

❓构造函数/析构函数中有 this吗？

有。构造函数中 this指向正在构建的对象；析构函数中 this指向正在销毁的对象。

补充：

  1. 在早期的 C++ 代码（或某些底层库）中，有时会看到显式的 this调用，而在现代 C++ 中，它通常被隐式处理。

    // 早期风格（显式传递 this）
    void func(Person* this);

    // 现代风格（编译器隐式处理）
    void Person::func() {
    // 直接使用成员变量，编译器自动添加 this->
    }

  2. CRTP（奇异递归模板模式）中 this的特殊用法

在 CRTP 中，基类通过将 this转换为派生类指针（static_cast<Derived*>(this)）来实现静态多态

构造函数、析构函数是否为虚函数

函数类型 能否为虚函数 核心原因 要点
构造函数 绝对不能 虚函数依赖 vptr，而 vptr 是在构造函数中初始化的。 解释“先有鸡还是先有蛋”的依赖悖论。
析构函数 必须是（基类） 确保通过基类指针删除派生类对象时，派生类的资源能被正确释放。 强调 Rule of Three/Five 和防止内存泄漏。

构造函数不能是虚函数

对象创建顺序：构造函数负责初始化对象，包括设置 vptr（虚函数表指针）。如果构造函数是虚函数，调用前就需要通过 vptr 查找地址，但此时 vptr 还未被初始化（因为构造函数还没执行）。这形成了逻辑死循环。

编译期绑定：构造函数的调用在编译期就已经确定（例如 new Derived()明确调用 Derived::Derived()），不需要运行期多态。

语义矛盾：构造函数的作用是“从无到有”创建一个对象，而虚函数是为了处理“已有对象”的多态行为。

基类析构函数必须是虚函数

Base* ptr = new Derived();

如果 ~Base()不是虚函数，执行 delete ptr;时，只会调用 Base的析构函数，而不会调用 Derived的析构函数。

导致资源泄漏（Derived 中申请的堆内存、文件句柄等未被释放）。

将基类的析构函数声明为 virtual。这样删除 ptr时，会先调用 Derived::Derived()，再调用 Base::Base()，确保资源彻底清理。

追问

❓所有的析构函数都必须加 virtual 吗？

不是。只有当该类打算作为基类被继承，并且会通过基类指针操作派生类对象时，才需要虚析构函数。如果一个类不会被继承（如 std::string），加 virtual 会带来不必要的 vptr 开销。

❓构造函数可以是私有的吗？

可以。这是设计模式中的常见用法（如单例模式 Singleton），通过私有构造函数禁止外部直接实例化，强制通过静态接口获取对象。

❓虚构造函数（Virtual Constructor）存在吗？

语法上不存在。但可以通过工厂模式（Factory Pattern）模拟。定义一个虚函数 clone()，它在内部调用构造函数并返回新对象，实现“多态地创建对象”。

成员模板函数（Member Template Functions）不能是 virtual（虚函数）

编译器无法在编译阶段为一个“还不知道会有多少种形态”的模板函数构建一个固定的虚函数表。

机制 特性 冲突点
模板 (Templates) 编译期生成代码。每使用一种新的类型实例化模板，编译器就会生成一份新的函数代码。 虚函数表（vtable）需要在编译期确定大小。如果允许虚模板函数，编译器无法预知需要为多少个实例化版本预留 vtable 槽位。
虚函数 (Virtual) 运行期通过 vtable 动态绑定。vtable 是一个固定大小的数组，存储着函数指针。 模板实例化可能导致函数数量无限增长，这与 vtable 的固定结构不兼容。
在工程实践中，可以通过以下设计模式绕过限制:
  1. 类型擦除（Type Erasure）—— 最常用

现代 C++（如 std::function、std::any）的核心技术。通过一层间接层，将具体的模板类型包装成一个非模板的基类接口。

// 非模板基类
class Processor {
public:
    virtual void process() = 0; // 虚函数
    virtual ~Processor() = default;
};

// 模板派生类
template<typename T>
class ConcreteProcessor : public Processor {
    T data;
public:
    ConcreteProcessor(T d) : data(d) {}
    void process() override { /* 使用 data */ }
};

在编译期“擦除”掉具体类型的详细信息，只保留其对外暴露的行为接口，从而使不同具体类型的对象能够通过同一个静态类型（如基类指针）进行统一管理。

  1. CRTP（奇异递归模板模式）

利用模板实现静态多态，完全避开虚函数机制，从而在编译期获得多态的效果，且无运行时开销。

template<typename Derived>
class Base {
    public:
        void interface() {
            static_cast<Derived*>(this)->implementation(); // 静态绑定
    }
};
  1. 使用 std::variant和std::visit

在 C++17 中，可以通过 std::visit访问 variant，实现一种不使用继承和虚函数的多态。

方案 机制 优点 缺点
类型擦除​ 运行时多态 + 模板 接口统一，对用户友好（如 std::function）。 有一定的性能开销（间接层、堆分配）。
CRTP​ 编译期多态 零运行时开销，性能最好。 侵入式设计，类型必须在编译期确定。
std::variant​ 编译期访问 类型安全，无继承耦合。 只能处理有限集合的类型（variant 中定义的类型）。

sizeof 一个空类大小是多大

大小为 1字节。

❓为什么不是 0？-用作占位，确保每个对象都有独一无二的内存地址。

C++ 标准规定：任何两个不同的对象必须拥有不同的地址。如果空类的大小为 0，那么当你创建该类的数组或连续对象时，就会出现多个对象地址相同的情况，这违反了对象唯一性原则。

特殊情况：空基类优化 (EBO)

当一个空类作为基类时，编译器通常会执行 Empty Base Optimization (空基类优化)，使得基类不占用额外空间。

class Empty {};

class Derived : public Empty {
    int x;
};

class Composed {
    Empty e;
    int x;
};

int main() {
    cout << sizeof(Derived) << endl; // 输出 4 (仅 int 的大小)
    cout << sizeof(Composed) << endl; // 输出 8 (1字节Empty + 3字节对齐 + 4字节int)
}

继承空类：通常不增加大小（EBO 生效）。

包含空类对象（作为一个成员变量）：会增加大小（受对齐影响）。

进阶变化

场景 sizeof结果 原因分析
空类 1 占位符，保证地址唯一。
空类 + 虚函数 8 (64位) 增加了一个 vptr (虚指针) 的大小。
空类 + 成员 int 4 成员占用空间，1字节的空类占位通常被优化掉（对齐后）。
空类 + 静态成员 1 静态成员不存储在对象实例中，不影响大小。

补充: C++20 引入了 [[no_unique_address]]属性，允许即使是作为成员变量的空类，也可以像 EBO 一样不占用空间。

扩展：进阶与设计思想

  1. RAII（Resource Acquisition Is Initialization）

将资源（内存、文件句柄、锁）的生命周期绑定到对象上。面试高频术语。它是 C++ 区别于 Java/C# 的重要特征。

应用：智能指针（std::unique_ptr, std::shared_ptr）是 RAII 的最佳实践。

  1. 接口隔离与依赖倒置

面向接口编程，而非面向实现编程。利用抽象类（接口）降低模块间的耦合度。

  1. Rule of Three/Five/Zero

如果你需要手动管理资源（如内存、文件句柄），你就必须同时定义拷贝构造、拷贝赋值和析构函数；在 C++11 及以后，还需加上移动构造和移动赋值。

规则 组成成员 适用场景
Rule of Three (C++98) 1. 析构函数
2. 拷贝构造函数
3. 拷贝赋值运算符		 管理动态内存或独占资源的类。
Rule of Five (C++11+) Rule of Three +
4. 移动构造函数
5. 移动赋值运算符		 需要优化性能，支持资源所有权转移的类中。
Rule of Zero (现代 C++) 一个都不用写 使用 std::string, std::vector, std::unique_ptr等智能资源管理类。
目的：对称性和防止浅拷贝灾难。

析构函数：负责释放资源；

拷贝构造/赋值：负责深拷贝。默认执行浅拷贝（复制指针地址）。这会导致两个对象指向同一块内存，析构时触发 Double Free（双重释放），程序崩溃。

移动构造/赋值：负责转移资源所有权。避免不必要的深拷贝，提升性能（例如从临时对象“偷”走数据）。

//一个符合 Rule of Five 的字符串类
class MyString {
private:
    char* data;
    size_t length;

public:
    // 1. 构造函数
    MyString(const char* str = "") : length(strlen(str)) {
        data = new char[length + 1];
        strcpy(data, str);
    }
    
        // 2. 析构函数 (Rule of Three)
        ~MyString() { delete[] data; }
    
        // 3. 拷贝构造函数 (深拷贝)
        MyString(const MyString& other) : length(other.length) {
            data = new char[length + 1];
            strcpy(data, other.data);
        }
    
        // 4. 拷贝赋值运算符
        MyString& operator=(const MyString& other) {
            if (this == &other) return *this; // 防自赋值
    
            delete[] data; // 释放旧资源
            length = other.length;
            data = new char[length + 1];
            strcpy(data, other.data);
            return *this;
        }
    
        // 5. 移动构造函数 (C++11)
        MyString(MyString&& other) noexcept 
            : data(other.data), length(other.length) {
            other.data = nullptr; // 关键：置空源对象，防止其析构时释放内存
            other.length = 0;
        }
    
        // 6. 移动赋值运算符 (C++11)
        MyString& operator=(MyString&& other) noexcept {
            if (this == &other) return *this;
            
            delete[] data; // 清理自身旧资源
            data = other.data;
            length = other.length;
            other.data = nullptr; // 剥夺源对象资源
            return *this;
        }
};

  1. vptr和vtable工作原理（调用流程）

    class Base {
    public:
    virtual void foo() { cout << “Base::foo” << endl; }
    virtual void bar() { cout << “Base::bar” << endl; }
    };

    class Derived : public Base {
    public:
    void foo() override { cout << “Derived::foo” << endl; } // 重写
    };

    int main() {
    Base* obj = new Derived();
    obj->foo(); // 调用 Derived::foo
    }

vtable 布局：

Base的 vtable: [ &Base::foo ][ &Base::bar ]

Derived的 vtable: [ &Derived::foo ][ &Base::bar ] (覆盖了 foo)

对象创建：

new Derived()创建的对象，其内部的 vptr指向 Derived类的 vtable。

调用 obj->foo()：

编译器看到 obj是 Base*类型，但发现 foo()是虚函数。

从 obj中取出 vptr。

找到 Derived的 vtable。

取出 vtable 中第一个槽位（索引0）的函数地址（即 &Derived::foo）。

调用该函数。

❓vptr和 vtable存放在哪里？

vptr存放在对象内部，vptr 是对象实例的一部分，占用对象的内存空间（通常是 8 字节，取决于系统位数）。

vtable是属于类的，通常存放在程序的只读数据段（.rodata）中。

❓构造函数中调用虚函数会发生什么？

不会有多态。在构造函数执行期间，对象的动态类型是当前正在构造的类。例如，在 Base构造函数中调用虚函数，只会调用 Base的版本，即使对象实际是 Derived。这是因为此时 vptr正指向 Base的 vtable。

❓析构函数中调用虚函数呢？

同样不会有多态。在析构函数执行时，对象的类型会逐步退化。当执行基类析构函数时，vptr已经指回基类的 vtable，因此调用的是基类的版本。这也是为什么基类析构函数必须是虚函数的原因（确保 delete basePtr时能正确调用派生类析构）。

❓多重继承下的 vptr？

如果一个类继承了两个带有虚函数的基类，它可能会有多个 vptr（每个基类对应一个），或者通过一个复杂的 vtable 布局来处理。这是 C++ 对象模型中最复杂的部分之一。

性能与开销总结：

开销类型 说明 影响程度
空间开销 每个对象增加一个指针大小（vptr）。 小，但对于大量微小对象有影响。
时间开销 调用时需经过两次寻址（vptr -> vtable -> func）。 极小，现代 CPU 分支预测能缓解。
无法内联 虚函数调用在编译期无法确定，因此无法内联。 中等，失去内联优化的性能红利。

补充： CRTP或 std::variant作为避免 vptr 开销的替代方案

  1. 析构函数的调用顺序

析构函数的调用顺序是“先派生类，后基类”（LIFO，后进先出）。这与构造函数的顺序（先基类，后派生类）正好相反。

❓为什么必须是这个顺序？

依赖关系：派生类对象是在基类对象的基础上构建的（“is-a”关系）。派生类的析构函数可能依赖基类提供的资源或状态。如果先销毁基类，派生类析构时访问基类成员将导致未定义行为（访问已释放的内存）。

资源安全：确保派生类特有的资源（如上例中的 data）在基类资源释放之前被清理，防止悬空引用。

❗如果基类析构函数不是虚函数，且通过基类指针删除派生类对象：

结果：仅调用基类析构函数，派生类析构函数不会被调用。

后果：派生类中的资源（如 new的内存）无法释放，造成内存泄漏。

结论：凡是可能被继承的基类，其析构函数必须声明为 virtual。

多重继承：派生类 →第二个基类 →第一个基类（按继承列表逆序）

现代 C++ 建议：使用 RAII​ 原则管理资源，并确保基类析构函数为 virtual或 protected（禁止直接删除基类指针）
