算法与数据结构

复习排序算法的时间复杂度、红黑树等经典数据结构的原理等。

数据结构&算法

数据结构–数据的存储与组织

数组（Array）—— 基础存储

内存连续，支持通过下标进行 O(1) 的随机访问。

链表（Linked List）—— 灵活存储

内存离散，通过指针将节点串联。彻底解决了数组插入删除慢、大小受限的问题，实现了动态的内存分配。

栈与队列（Stack & Queue）—— 逻辑约束

它们通常基于数组或链表实现，但在操作上施加了严格的规则。

树（Tree）—— 层次关系

从线性结构跨越到非线性结构，用于表达“一对多”的层次关系。

哈希表（Hash Table）—— 高效检索

数据结构的集大成者。底层通常由“数组 + 链表/红黑树”构成。

算法–问题的求解策略

枚举（暴力法）—— 思维起点

列举所有可能的情况，逐一验证直到找到答案。

递归（Recursion）—— 化繁为简

🔄 第二部分：经典排序算法复杂度速查表

在面试写代码时，如果你说“我这里用一个排序”，一定要瞬间反应出你用的排序是啥复杂度。

排序算法 最佳时间 平均时间 最坏时间 空间复杂度 稳定性 面试适用场景
快速排序 (Quick) O(n log n) O(n log n) O(n²) O(log n) 不稳定 工业界最爱，缓存友好，但小心最坏情况
归并排序 (Merge) O(n log n) O(n log n) O(n log n) O(n) 稳定 外部排序、链表排序，不怕最坏情况
堆排序 (Heap) O(n log n) O(n log n) O(n log n) O(1) 不稳定 Top K 问题，priority_queue的基石
冒泡 / 插入 / 选择 O(n) O(n²) O(n²) O(1) 稳定 面试基本不问实现，只问优化（如插入排序对近乎有序数组极快）
计数/桶/基数排序 O(n+k) O(n+k) O(n²) O(n+k) 稳定 数据范围小、整数排序，面试常考思想

(注：C++ STL 中的 std::sort 通常是一种内省排序（IntroSort），它是快速排序、堆排序和插入排序的混合体，最坏时间复杂度稳定在 O(n log n)。)

🧠 第三部分：面试必考“潜规则”与易错点

光背表格是不够的，面试官往往会在这些细节上给你挖坑。

1. vector 的“扩容”陷阱

  • 现象：vector 初始容量为0，随着 push_back 会触发扩容（通常按2倍或1.5倍）。
  • 代价：扩容意味着 申请新内存 -> 拷贝旧元素 -> 释放旧内存，单次 push 最坏可达 O(n)。
  • 破局：如果事先知道大概要存多少数据，务必使用 reserve(n) 预先分配内存，这能把后续插入统统拉回 O(1)！

2. 递归的隐藏成本：空间复杂度

  • 只看时间不看空间。比如经典的斐波那契数列递归求法：
  • 时间复杂度：惊人的 O(2ⁿ) （呈指数爆炸）。
  • 空间复杂度：O(n) （由于系统调用栈的深度，最深的递归分支会一直压栈直到基线条件）。

3. unordered_map 的哈希冲突

  • 虽然平均是 O(1)，但如果你的哈希函数写得太烂（比如把所有元素都映射到同一个桶里），哈希表就会退化成链表，查找复杂度瞬间飙升至 O(n)。

4. 遍历中修改容器（迭代器失效）

  • vector 插入/删除：会导致元素移动，指向插入/删除点及之后的迭代器全部失效。
  • map / set 插入/删除：红黑树的旋转变色，只会导致当前被删除元素的迭代器失效，其他不受影响。
  • unordered_map 插入：可能会导致全局重哈希（Rehash），此时所有迭代器全部失效。

💡 面试实战：
当在面试中准备写代码时，可以：一边写一边口述复杂度。
比如：“这里我选用 unordered_map 来存访过的元素，因为平均查找是 O(1)，整体算法时间复杂度可以控制在 O(n)，空间复杂度也是 O(n)。”

🎯 C++ 面试 · 复杂度追问清单

一、数组 & vector（最常被追问）

❓ Q1：push_back() 是 O(1) 吗？

✅ 标准答法：

平均 O(1)，均摊 O(1)
发生扩容时是 O(n)，但均摊下来仍是 O(1)

📌 加分点：

  • 扩容通常是 ×2
  • 扩容会导致迭代器全部失效

❓ Q2：vector 插入中间是 O(n) 为什么？

✅ 答：

需要整体移动元素

📌 追问延伸：

  • list 插入是 O(1)
  • 但 list 不能随机访问

二、哈希表（unordered_map / set）

❓ Q3：unordered_map 查找一定是 O(1) 吗？

✅ 标准答法：

平均 O(1)，最坏 O(n)

📌 必补一句：

当所有 key 都哈希冲突时，退化为链表（C++11 后是桶）

❓ Q4：为什么 map 不用哈希表？

✅ 答：

map 需要有序遍历，哈希表无序
红黑树稳定 O(log n)，适合范围查询

❓ Q5：unordered_map 和 unordered_set 区别？

✅ 答：

只存 key vs 存 key-value
复杂度完全一致

三、排序 & STL sort

❓ Q6：std::sort 是快排吗？

✅ 标准答法：

Introsort（内省排序）

  • 快排
  • 深度过深转堆排
  • 小规模转插排

📌 复杂度：

O(n log n)，最坏也是 O(n log n)

❓ Q7：为什么快排最坏 O(n²)？

✅ 答：

每次选到最小 / 最大元素
常见于已排序数组

四、递归 & 栈空间

❓ Q8：递归 Fibonacci 的时间复杂度？

✅ 答：

O(2ⁿ)（指数级）

📌 追问：

  • 如何优化？
    • 记忆化 → O(n)
    • 迭代 → O(n)

❓ Q9：递归的空间复杂度怎么算？

✅ 答：

等于递归深度

  • 二叉树递归：O(h)
  • 链表递归：O(n)

五、树 & 图

❓ Q10：BST 查找为什么是 O(log n)？

✅ 答：

前提是平衡

  • 最坏（退化成链表）：O(n)

❓ Q11：红黑树比 AVL 快在哪？

✅ 答：

旋转更少，插入更快
查询略慢，综合性能更好

❓ Q12：图的 DFS / BFS 复杂度？

✅ 答：

O(V + E)
V：顶点数，E：边数

六、堆 & priority_queue

❓ Q13：建堆为什么是 O(n) 不是 O(n log n)？

✅ 关键点：

大多数节点在底层，调整成本低
数学推导结果是 O(n)

📌 必会：

  • 插入 / 删除：O(log n)
  • 取堆顶：O(1)

七、经典陷阱题（高频）

问题 正确回答
vector::size() O(1)
list::size()（老标准） O(n)
map::find() O(log n)
unordered_map::rehash() O(n)
递归 vs 迭代 递归多了栈空间
原地算法 空间 O(1)

八、面试“保命话术”（直接用）

✅ 被问复杂度来源：

“这个复杂度来源于 XXX 操作，每一步……”

✅ 不确定时：

“平均情况下是 O(n log n)，最坏可能退化到 O(n²)。”

✅ 对比型问题：

“如果用哈希表，可以把时间从 O(n²) 降到 O(n)，但牺牲了空间。”

九、练习方式

✅ 对着代码说复杂度
✅ 每道题必须说：

  • 时间复杂度
  • 空间复杂度
  • 是否可优化

快速排序和归并排序有什么区别

快速排序（Quick Sort）和归并排序（Merge Sort）都是分治思想的经典排序算法，但在核心逻辑、性能特性和适用场景上有本质区别。

一、核心区别一览表（面试必背）

对比点 快速排序 归并排序
分治方式 选 pivot（基准） 直接二分
分区策略 原地交换 额外数组合并
是否原地 ✅ 是 ❌ 否
是否稳定 ❌ 不稳定 ✅ 稳定
最好/平均 O(n log n) O(n log n)
最坏 O(n²) O(n log n)
空间复杂度 O(log n)（递归栈） O(n)
缓存友好 ✅ 非常友好 ❌ 较差
适用场景 数组、随机数据 链表、外部排序

二、核心思想对比

快速排序（挖坑 + 填坑）

选一个基准，小的放左边，大的放右边

  • 递归处理左右区间
  • 不需要 merge

📌 关键点：partition 是灵魂

归并排序（先分后合）

一直拆分，直到单个元素，再合并

  • 合并过程需要额外空间
  • 合并逻辑是核心

四、时间与空间复杂度

时间复杂度

情况 快排 归并
最好 O(n log n) O(n log n)
平均 O(n log n) O(n log n)
最坏 O(n²) O(n log n)

⚠️ 快排最坏发生在：

  • 数组已排序
  • pivot 总是选最小 / 最大

✅ 优化方式：

  • 随机选 pivot
  • 三数取中

空间复杂度

算法 原因
快排 递归栈 O(log n)
归并 额外数组 O(n)

五、为什么 STL 用快排（ introsort ）

std::sort 实际使用：

IntroSort = Quick Sort + Heap Sort + Insertion Sort

原因：

  • 快排 缓存命中率高
  • 实战最快
  • 最坏情况自动降级为堆排序

📌 面试可以这样答：

快排在真实数据上常数更小，而归并排序额外内存开销大。

六、链表排序选哪个？

✅ 归并排序

  • 链表不能随机访问
  • 快排 pivot 移动成本高
  • 归并排序只需指针操作

📌 LeetCode 148：链表排序 = 归并排序

七、一句话总结

快排：快、省内存、不稳定，适合数组；
归并：稳、慢一点、耗内存，适合链表和外部排序。

八、面试官常追问

问题 标准回答
快排为什么快？ 原地、缓存友好
归并排序缺点？ 额外空间
什么时候用归并？ 稳定、链表、大数据
快排最坏怎么解决？ 随机 pivot / introsort
