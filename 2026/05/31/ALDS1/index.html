🧩 第一部分：C++ STL 容器复杂度速查表

底层实现决定了上层建筑，记住它们的最好方法就是结合它们的底层数据结构来理解。

1. 序列式容器 (Sequence Containers)

容器 底层结构 核心操作 时间复杂度 空间复杂度 面试记忆口诀
vector 动态数组 随机访问 ([]) O(1) O(n) 尾部快，中间慢
尾部插入/删除 (push_back/pop_back) 均摊 O(1) 随机访问秒杀一切
中间/头部插入删除 O(n)
deque 分段连续空间 头尾插入/删除 (push/pop) O(1) O(n) 双端无忧，中段受罪
随机访问 O(1) 兼顾首尾效率
list 双向链表 任意位置插入/删除 O(1) (已知位置) O(n) 插删无敌，访问拉胯
随机访问 O(n) 不支持下标访问
forward_list 单向链表 任意位置插入/删除 O(1) (已知位置) O(n) 比list更省内存
随机访问 O(n) 只能往前走

2. 关联式容器 (Associative Containers)

容器 底层结构 核心操作 时间复杂度 面试记忆口诀
set / map 红黑树 (平衡BST) 插入 / 删除 / 查找 O(log n) 自带排序，稳如老狗
multiset / multimap 红黑树 插入 / 删除 / 查找 O(log n) 允许重复，同样稳定logN

(注：map的key唯一，multimap允许重复key)

3. 无序关联容器 (Unordered Containers) —— 面试高频雷区！

容器 底层结构 核心操作 平均时间复杂度 最坏时间复杂度 面试记忆口诀
unordered_set 哈希表 (拉链法) 插入 / 删除 / 查找 O(1) O(n) 理想很丰满(O1)
unordered_map 哈希表 (拉链法) 插入 / 删除 / 查找 O(1) O(n) 现实可能很骨感(On)
(注：unordered允许你用自定义对象做key，但必须重写==运算符和哈希函数)

4. 容器适配器 (Container Adapters)

容器 底层默认结构 核心操作 时间复杂度 面试记忆口诀
stack deque (可指定) push / pop / top O(1) 后进先出(LIFO)
queue deque (可指定) push / pop / front O(1) 先进先出(FIFO)
priority_queue vector (大顶堆) push / pop / top O(log n) VIP插队，顶部最大

🔄 第二部分：经典排序算法复杂度速查表

在面试写代码时，如果你说“我这里用一个排序”，一定要瞬间反应出你用的排序是啥复杂度。

排序算法 最佳时间 平均时间 最坏时间 空间复杂度 稳定性 面试适用场景
快速排序 (Quick) O(n log n) O(n log n) O(n²) O(log n) 不稳定 工业界最爱，缓存友好，但小心最坏情况
归并排序 (Merge) O(n log n) O(n log n) O(n log n) O(n) 稳定 外部排序、链表排序，不怕最坏情况
堆排序 (Heap) O(n log n) O(n log n) O(n log n) O(1) 不稳定 Top K 问题，priority_queue的基石
冒泡 / 插入 / 选择 O(n) O(n²) O(n²) O(1) 稳定 面试基本不问实现，只问优化（如插入排序对近乎有序数组极快）
计数/桶/基数排序 O(n+k) O(n+k) O(n²) O(n+k) 稳定 数据范围小、整数排序，面试常考思想

(注：C++ STL 中的 std::sort 通常是一种内省排序（IntroSort），它是快速排序、堆排序和插入排序的混合体，最坏时间复杂度稳定在 O(n log n)。)

🧠 第三部分：面试必考“潜规则”与易错点

光背表格是不够的，面试官往往会在这些细节上给你挖坑。

1. vector 的“扩容”陷阱

  • 现象：vector 初始容量为0，随着 push_back 会触发扩容（通常按2倍或1.5倍）。
  • 代价：扩容意味着 申请新内存 -> 拷贝旧元素 -> 释放旧内存，单次 push 最坏可达 O(n)。
  • 破局：如果事先知道大概要存多少数据，务必使用 reserve(n) 预先分配内存，这能把后续插入统统拉回 O(1)！

2. 递归的隐藏成本：空间复杂度

  • 很多同学算复杂度只看时间不看空间。比如经典的斐波那契数列递归求法：
  • 时间复杂度：惊人的 O(2ⁿ) （呈指数爆炸）。
  • 空间复杂度：O(n) （由于系统调用栈的深度，最深的递归分支会一直压栈直到基线条件）。

3. unordered_map 的哈希冲突

  • 虽然平均是 O(1)，但如果你的哈希函数写得太烂（比如把所有元素都映射到同一个桶里），哈希表就会退化成链表，查找复杂度瞬间飙升至 O(n)。这也是为什么面试有时会让手写一个简单的哈希表。

4. 遍历中修改容器（迭代器失效）

  • vector 插入/删除：会导致元素移动，指向插入/删除点及之后的迭代器全部失效。
  • map / set 插入/删除：红黑树的旋转变色，只会导致当前被删除元素的迭代器失效，其他不受影响。
  • unordered_map 插入：可能会导致全局重哈希（Rehash），此时所有迭代器全部失效。

💡 面试实战小贴士：
当你在面试中准备写代码时，养成好习惯：一边写一边口述复杂度。
比如：“这里我选用 unordered_map 来存访过的元素，因为平均查找是 O(1)，整体算法时间复杂度可以控制在 O(n)，空间复杂度也是 O(n)。”
这句话一出口，面试官立刻就知道你是个老手了。
